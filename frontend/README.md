# InterviewHub — фронтенд

React 19 + TypeScript + Vite 8, Tailwind 4.

## Запуск

Сначала поднимите API на 5199 (см. корневой `PLAN.md`), затем:

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173
```

Vite проксирует `/api` на `http://localhost:5199` — фронт ходит по
относительным путям и в dev, и в проде за nginx, поэтому адрес API
в коде нигде не зашит. Переопределяется через `VITE_API_TARGET`.

```bash
npm run build    # tsc -b && vite build -> dist/
npm run lint     # oxlint
npm run smoke    # дымовые тесты (нужен запущенный API)
```

### Дымовые тесты

```bash
VITE_API_URL=http://localhost:5199 npm run smoke
```

Четыре проверки, все против живого API:

- `smoke/render.tsx` — рендерит каждый публичный роут через `react-dom/server`
  и ищет в разметке ожидаемый текст. Ловит то, что не ловит `tsc`:
  упавший хук, разъехавшуюся форму ответа, обращение к `undefined`.
- `smoke/admin.tsx` — то же для админки под залогиненным админом, плюс
  жизненный цикл вопроса (создание → ответ → смена статуса → удаление)
  и проверка, что bulk-действие не стирает тело вопроса.
- `smoke/markdown.tsx` — разметка markdown, экранирование сырого HTML,
  отсутствие невалидной вложенности.
- `smoke/shiki.mjs` — highlighter собирается и отдаёт обе темы.

jsdom для этого не годится: он не исполняет `<script type="module">`,
поэтому SPA в нём не стартует вовсе.

## Структура

```
src/
  app/router.tsx      роуты; админка грузится отдельным чанком (lazy)
  components/         Layout, AdminLayout, ErrorBoundary, ProtectedRoute
    ui/               Button, Card, Badge, Skeleton, CategoryIcon,
                      CompanyLogo, DifficultyDots, Pagination, States
  components/         + Markdown, QuestionCard, QuestionFilters,
                      QuestionShowcase, Toaster
    ui/               + Modal, ConfirmDialog, Field
  lib/                api (axios + refresh), hooks (TanStack Query), utils
  store/              authStore, themeStore
  types/api.ts        типы ответов API, написаны вручную по DTO бэкенда
  pages/              публичные страницы и admin/
  index.css           дизайн-токены в три слоя
smoke/                дымовые тесты против живого API
```

## Дизайн-токены

Три слоя в `index.css`, менять только в этом порядке:

1. **primitive** — сырая палитра (`--color-slate-900`, `--color-brand-500`).
   Компоненты их напрямую не используют.
2. **semantic** — роли (`--ih-surface`, `--ih-fg-muted`, `--ih-accent`).
   Только этот слой меняется при переключении темы.
3. **component** — размеры (`--radius-card`, `--size-header`, `--spacing-page-x`).

Компонент, взявший primitive напрямую, останется тёмным в светлой теме —
это и есть причина разделения.

Тёмная тема по умолчанию. Класс `dark` ставит инлайн-скрипт в `index.html`
до первой отрисовки, иначе страница мигает светлым фоном. Ключ `ih-theme`
продублирован в `store/themeStore.ts` — при переименовании править оба места.

## Аутентификация

Access-токен живёт в памяти (15 минут), refresh — в `localStorage`
(ключ `ih-refresh`), потому что API отдаёт его в теле ответа, а не в cookie.
При 401 интерсептор в `lib/api.ts` меняет refresh на новую пару и повторяет
запрос; параллельные 401 разделяют один промис, чтобы не слать несколько
refresh сразу. Бэкенд ротирует токены — ответ сохраняется целиком, иначе
следующий refresh получит 401.

## Размер бандла

Две библиотеки норовят утащить в сборку всё разом — обе обузданы, не откатывать:

- **shiki** импортируется как `shiki/core` плюс грамматики поштучно.
  Точка входа `shiki` тянет bundle-full — все ~200 языков (Wolfram, Emacs Lisp,
  C++), это лишние ~4 МБ. Список `langs` в конфиге highlighter от этого
  не спасает: он про регистрацию, а не про то, что попадёт в бандл.
- **lucide-react** — иконка категории резолвится через `lucide-react/dynamic`.
  Барельный `import { icons }` затаскивает все ~1600 иконок (≈800 кБ),
  хотя реально используются единицы.

Плюс `Markdown` — ленивая обёртка: react-markdown, micromark и shiki
нужны только на странице вопроса, а статический импорт клал их
в основной бандл, который грузят и главная, и каталог.

## Админка

Записывающие операции идут через `lib/adminHooks.ts`. Общая обвязка мутаций
показывает тост и сбрасывает кэш; сообщения об ошибках берутся из ответа
бэкенда как есть — он отвечает осмысленно («Категория используется
в 5 вопросах», «Это последний активный админ»), и заменять это
на «Что-то пошло не так» было бы потерей информации.

**`PUT /api/admin/questions/{id}` — это полное состояние, а не патч.**
Бэкенд пишет `Body = input.Body` как есть, поэтому `body: null` стирает
постановку вопроса. Карточка списка тела не содержит — массовая смена
статуса поэтому сначала запрашивает деталь каждого вопроса и только потом
шлёт PUT. Лишний запрос дешевле потери текста; проверяется в `smoke/admin.tsx`.

Разграничение ролей продублировано на фронте и на бэкенде: `AdminLayout`
не показывает вкладку пользователей редактору, `ProtectedRoute requireAdmin`
не пускает на роут, а `/api/admin/users` в любом случае отвечает 403.
