Задачи вида «найти лучший непрерывный подмассив» или «самую длинную подстроку с условием» в лоб решаются перебором всех отрезков: O(n²) отрезков, и на каждый ещё O(n), чтобы посчитать сумму или проверить символы. Скользящее окно делает то же за один проход. Это частный случай двух указателей из статьи `Два указателя`: оба индекса идут в одну сторону, и интересует отрезок между ними.

## Идея

Окно — отрезок `[left, right]`, для которого поддерживается **состояние**: сумма, счётчики символов, число различных элементов. Главное слово — инкрементально. Когда окно сдвигается, мы не пересчитываем состояние с нуля, а добавляем вошедший элемент и вычитаем вышедший. Обновление стоит O(1), поэтому весь проход — O(n).

Бывает два вида окон:

- **фиксированного размера** k — оба края сдвигаются вместе;
- **переменного размера** — правый край расширяет окно, левый сжимает его, пока условие нарушено.

## Как узнать задачу

- в условии «подряд идущие», «подмассив», «подстрока», «отрезок», а не «подпоследовательность»;
- нужен максимум, минимум или самая длинная/короткая длина при условии;
- условие **монотонно**: если отрезок нарушает его, то любой отрезок, который его содержит, тоже нарушает (или наоборот — расширение только «ухудшает», сжатие только «улучшает»).

Последний пункт — тот, о котором забывают. Без монотонности окно даёт неверный ответ, и об этом ниже.

## Окно фиксированного размера

Максимальная сумма k подряд идущих элементов:

```csharp
static long MaxSumOfK(int[] a, int k)
{
    if (k <= 0 || k > a.Length) throw new ArgumentOutOfRangeException(nameof(k));
    long sum = 0;
    for (int i = 0; i < k; i++) sum += a[i];
    long best = sum;
    for (int i = k; i < a.Length; i++)
    {
        sum += a[i] - a[i - k];
        best = Math.Max(best, sum);
    }
    return best;
}
```

Первое окно считается целиком, дальше каждое следующее — одной строкой: вошёл `a[i]`, вышел `a[i - k]`. Для `[2, 1, 5, 1, 3, 2]` и k = 3 ответ 9. `best` инициализирован суммой первого окна, а не нулём: на `[-5, -2, -3]` с k = 2 правильный ответ −5, а ноль дал бы несуществующее окно.

Тот же каркас решает поиск анаграмм шаблона в строке: окно длиной шаблона и два массива счётчиков.

```csharp
static List<int> FindAnagrams(string s, string p)
{
    var result = new List<int>();
    if (p.Length > s.Length) return result;
    var need = new int[26];
    var have = new int[26];
    foreach (char c in p) need[c - 'a']++;
    for (int right = 0; right < s.Length; right++)
    {
        have[s[right] - 'a']++;
        if (right >= p.Length) have[s[right - p.Length] - 'a']--;
        if (right >= p.Length - 1 && have.AsSpan().SequenceEqual(need))
            result.Add(right - p.Length + 1);
    }
    return result;
}
```

Для `"cbaebabacd"` и `"abc"` получаем позиции 0 и 6. Сравнение двух массивов по 26 элементов — константа, так что проход остаётся O(n). Массив вместо `Dictionary<char, int>` здесь уместен, потому что алфавит известен и мал; для произвольного Unicode нужен словарь.

## Окно переменного размера: общий шаблон

1. сдвинуть `right`, добавить элемент в состояние;
2. **пока** окно невалидно — убрать `a[left]` из состояния и сдвинуть `left`;
3. обновить ответ.

Самая длинная подстрока без повторяющихся символов:

```csharp
static int LongestUniqueSubstring(string s)
{
    var count = new Dictionary<char, int>();
    int best = 0, left = 0;
    for (int right = 0; right < s.Length; right++)
    {
        char c = s[right];
        count[c] = count.GetValueOrDefault(c) + 1;
        while (count[c] > 1)
        {
            count[s[left]]--;
            left++;
        }
        best = Math.Max(best, right - left + 1);
    }
    return best;
}
```

`"abcabcbb"` — 3, `"bbbbb"` — 1, `"pwwkew"` — 3, пустая строка — 0.

Почему вложенный `while` не делает алгоритм квадратичным: `left` только растёт и никогда не превысит `right`. За весь проход он сдвинется не больше n раз суммарно. Каждый элемент один раз входит в окно и не больше одного раза выходит — итого O(n). Это амортизированная оценка, и на собеседовании её стоит проговорить, потому что первый вопрос к такому коду — «а не O(n²) ли это?».

Есть вариант быстрее на константу: хранить последний индекс символа и перепрыгивать `left` сразу за повтор.

```csharp
static int LongestUniqueSubstringJump(string s)
{
    var lastIndex = new Dictionary<char, int>();
    int best = 0, left = 0;
    for (int right = 0; right < s.Length; right++)
    {
        if (lastIndex.TryGetValue(s[right], out int prev) && prev >= left)
            left = prev + 1;
        lastIndex[s[right]] = right;
        best = Math.Max(best, right - left + 1);
    }
    return best;
}
```

Проверка `prev >= left` обязательна: старый индекс может лежать левее окна, и тогда прыжок отбросит `left` назад. Без неё на строке `"abba"` получается 3 вместо 2 — при втором `a` левый край возвращается к индексу 1, и в окно попадают две `b`.

## Минимальное окно

Шаблон работает и в обратную сторону — когда ищем самое **короткое** окно, удовлетворяющее условию. Тогда ответ обновляется внутри `while`, пока окно ещё валидно:

```csharp
static int MinSubarrayLen(int[] a, int target)
{
    int best = int.MaxValue, left = 0;
    long sum = 0;
    for (int right = 0; right < a.Length; right++)
    {
        sum += a[right];
        while (sum >= target)
        {
            best = Math.Min(best, right - left + 1);
            sum -= a[left];
            left++;
        }
    }
    return best == int.MaxValue ? 0 : best;
}
```

Для `[2, 3, 1, 2, 4, 3]` и target = 7 ответ 2 (отрезок `[4, 3]`). Этот код **верен только для неотрицательных чисел** — следующий раздел о том, почему.

## Когда окно не работает

С отрицательными числами сумма окна перестаёт быть монотонной: расширение может её уменьшить, сжатие — увеличить. Тот же `MinSubarrayLen` на `[1, -1, 5]` с target = 5 возвращает 3, хотя правильный ответ 1 — отрезок `[5]`. Окно не умеет «откатить» левый край, а здесь выгодно было выбросить сразу два элемента, один из которых отрицательный.

Для «подмассивов с суммой ровно k» при любых знаках нужны **префиксные суммы со словарём**: сумма отрезка `(i, j]` равна `prefix[j] - prefix[i]`, значит, для каждого `j` нужно знать, сколько раз раньше встречался префикс `prefix[j] - k`.

```csharp
static int CountSubarraysWithSum(int[] a, int k)
{
    var seen = new Dictionary<long, int> { [0] = 1 };
    long prefix = 0;
    int count = 0;
    foreach (int x in a)
    {
        prefix += x;
        count += seen.GetValueOrDefault(prefix - k);
        seen[prefix] = seen.GetValueOrDefault(prefix) + 1;
    }
    return count;
}
```

Тоже O(n) по времени, но O(n) по памяти. Запись `[0] = 1` — пустой префикс, без неё теряются отрезки, начинающиеся с нулевого индекса. Для максимальной суммы подмассива без ограничения на длину окно тоже не подходит — там алгоритм Кадане, он разобран в статье `Максимальная сумма подмассива`.

## То же в бэкенде

Rate limiter со скользящим окном — та же идея, только окно по времени, а не по индексам:

```csharp
sealed class SlidingWindowLimiter(int limit, TimeSpan window)
{
    private readonly Queue<DateTime> _hits = new();

    public bool TryAcquire(DateTime now)
    {
        while (_hits.Count > 0 && now - _hits.Peek() >= window)
            _hits.Dequeue();
        if (_hits.Count >= limit) return false;
        _hits.Enqueue(now);
        return true;
    }
}
```

Лимит 3 запроса в секунду: запросы на 0, 100, 200 мс проходят, на 300 и 999 мс — отклоняются, на 1000 мс первый запрос выпадает из окна, и новый проходит. Память — O(limit) на клиента. Класс не потокобезопасен; в ASP.NET Core есть готовый `SlidingWindowRateLimiter`, который вместо отметок хранит счётчики по сегментам окна и потому тратит константу памяти.

## Сложность

Каждый элемент входит в окно один раз и выходит не больше одного раза: время O(n). Память — O(1) для суммы, O(размера алфавита) или O(k) для счётчиков. Для сравнения: перебор всех отрезков с пересчётом — O(n²) или O(n³), отрезки фиксированной длины без инкрементального обновления — O(n·k).

## Типичные ошибки

- **Применять окно без монотонности** — отрицательные числа, условие «ровно k». Ответ неверный, исключения нет.
- **`if` вместо `while` при сжатии** — окно сжимается на один шаг и остаётся невалидным.
- **Обновлять ответ не в том месте**: для максимального окна — после `while`, для минимального — внутри него.
- **Ошибка на единицу в длине**: длина `[left, right]` — `right - left + 1`.
- **`best = 0` при поиске максимума** на данных, где все значения отрицательные.
- **Прыжок `left` назад** в варианте с последним индексом без проверки `prev >= left`.

## Что стоит ответить на собеседовании

Скользящее окно — приём для задач о непрерывных подмассивах и подстроках: поддерживаем отрезок `[left, right]` и его состояние, а при сдвиге обновляем состояние инкрементально — добавили вошедший, убрали вышедший. Фиксированное окно — максимальная сумма k подряд, анаграммы; переменное — правый край расширяет, `while` двигает левый, пока окно невалидно, например самая длинная подстрока без повторов.

Обязательно объяснить, почему вложенный `while` даёт O(n), а не O(n²): `left` только растёт, и каждый элемент входит и выходит не больше одного раза. И назвать границу применимости — монотонность условия: с отрицательными числами окно ломается, а для «суммы ровно k» нужны префиксные суммы со словарём. В бэкенде та же идея — rate limiting и метрики за последние N секунд.
