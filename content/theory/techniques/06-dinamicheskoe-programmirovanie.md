Динамическое программирование пугает названием, но на уровне собеседования middle это одна идея: если рекурсивное решение много раз считает одно и то же, запомните результаты. Экспоненциальный перебор превращается в полиномиальный проход по таблице. Сложность не в коде — он обычно короче десяти строк, — а в том, чтобы правильно сформулировать, что хранится в ячейке таблицы.

## Идея

DP применимо, когда у задачи есть два свойства:

- **перекрывающиеся подзадачи** — рекурсия многократно приходит к одним и тем же входам;
- **оптимальная подструктура** — ответ на задачу собирается из ответов на подзадачи.

Классическая иллюстрация — числа Фибоначчи. Наивная рекурсия:

```csharp
static long FibNaive(int n) => n < 2 ? n : FibNaive(n - 1) + FibNaive(n - 2);
```

`FibNaive(40)` на .NET 10 сделал **331 160 281** вызов и считал около полсекунды, хотя различных подзадач всего 41. Каждый `F(k)` пересчитывается заново из обеих веток. Число вызовов растёт как φⁿ ≈ 1,618ⁿ: прибавьте к n десять — и вызовов станет в 123 раза больше.

## Два способа: сверху вниз и снизу вверх

**Мемоизация (top-down)** — та же рекурсия плюс кэш:

```csharp
static long FibMemo(int n, Dictionary<int, long> memo)
{
    if (n < 2) return n;
    if (memo.TryGetValue(n, out long cached)) return cached;
    long value = FibMemo(n - 1, memo) + FibMemo(n - 2, memo);
    memo[n] = value;
    return value;
}
```

Вызовов стало 79 вместо 331 миллиона. Плюс подхода — код почти не меняется и считаются только нужные подзадачи. Минус — рекурсия: глубина n, и всё сказанное в `Рекурсия и переполнение стека` применимо — на n порядка десятков тысяч процесс упадёт.

**Таблица (bottom-up)** — подзадачи считаются в таком порядке, чтобы к моменту расчёта ячейки все нужные уже были готовы:

```csharp
static long FibTable(int n)
{
    if (n < 2) return n;
    var dp = new long[n + 1];
    dp[1] = 1;
    for (int i = 2; i <= n; i++)
        dp[i] = checked(dp[i - 1] + dp[i - 2]);
    return dp[n];
}
```

Ни рекурсии, ни словаря, массив вместо хеш-таблицы. Если ячейка зависит только от нескольких предыдущих, всю таблицу хранить не нужно:

```csharp
static long Fib(int n)
{
    long prev = 0, cur = 1;
    if (n == 0) return 0;
    for (int i = 2; i <= n; i++)
        (prev, cur) = (cur, checked(prev + cur));
    return cur;
}
```

Время O(n), память O(1). `checked` здесь не для красоты: `F(92) = 7 540 113 804 746 346 429` — последнее число Фибоначчи, которое помещается в `long`, а `Fib(93)` бросает `OverflowException`. Без `checked` получилось бы тихое отрицательное число.

## Как узнать задачу

- просят **количество способов**, **минимум** или **максимум**, а не сами варианты;
- решение — последовательность выборов, и каждый выбор сводит задачу к меньшей того же вида;
- перебор очевиден, но экспоненциален;
- жадное решение напрашивается, но находится контрпример.

Если нужно перечислить все варианты, DP не поможет: ответ сам по себе экспоненциальный, и это работа для перебора с возвратом.

## Как построить решение

Четыре вопроса, ответы на которые и есть решение:

1. **Состояние** — что означает `dp[i]` (или `dp[i, j]`) словами. Например, «минимум монет, чтобы набрать сумму i».
2. **Переход** — как `dp[i]` выражается через меньшие состояния.
3. **База** — значения, которые известны без перехода.
4. **Порядок** — в каком порядке заполнять, чтобы зависимости были готовы.

Если состояние не удаётся сформулировать одной фразой, решение почти наверняка будет неверным, как бы аккуратно ни был написан цикл.

## Пример: размен монет

Минимальное число монет, чтобы набрать сумму. Жадный алгоритм — брать самую крупную монету, пока влезает, — ломается: для монет `{1, 3, 4}` и суммы 6 он даст `4 + 1 + 1`, три монеты, а оптимально `3 + 3`, две.

Состояние: `dp[s]` — минимум монет для суммы s. Переход: последняя монета — какая-то `coin`, значит `dp[s] = min(dp[s - coin] + 1)`. База: `dp[0] = 0`.

```csharp
static int MinCoins(int[] coins, int amount)
{
    var dp = new int[amount + 1];
    Array.Fill(dp, int.MaxValue);
    dp[0] = 0;
    for (int sum = 1; sum <= amount; sum++)
        foreach (int coin in coins)
            if (coin <= sum && dp[sum - coin] != int.MaxValue)
                dp[sum] = Math.Min(dp[sum], dp[sum - coin] + 1);
    return dp[amount] == int.MaxValue ? -1 : dp[amount];
}
```

Для `{1, 2, 5}` и 11 — 3 монеты, для `{2}` и 3 — −1, сумма недостижима. Проверка `!= int.MaxValue` защищает от переполнения: `int.MaxValue + 1` — отрицательное число, которое выиграло бы любой `Math.Min`. Время O(amount · coins), память O(amount).

**Порядок циклов меняет смысл.** Если считать число способов, важно, различаются ли `1 + 2` и `2 + 1`:

```csharp
static long CountCombinations(int[] coins, int amount)
{
    var dp = new long[amount + 1];
    dp[0] = 1;
    foreach (int coin in coins)
        for (int sum = coin; sum <= amount; sum++)
            dp[sum] += dp[sum - coin];
    return dp[amount];
}
```

Внешний цикл по монетам считает **сочетания**: каждая монета добавляется после всех предыдущих, и порядок внутри набора не учитывается. Для `{1, 2, 5}` и 5 — четыре способа. Если поменять циклы местами — внешний по сумме, внутренний по монетам, — тот же код посчитает **последовательности**, и ответ станет 9. Обе версии верны, но для разных задач; на собеседовании эту разницу любят спрашивать.

## Пример: редакционное расстояние

Минимальное число вставок, удалений и замен символа, чтобы превратить одну строку в другую. Это основа нечёткого поиска и подсказок «возможно, вы имели в виду».

Состояние: `dp[i, j]` — расстояние между первыми i символами `a` и первыми j символами `b`. Переход: если последние символы равны, замена бесплатна; иначе берём лучшее из замены, удаления и вставки. База: превратить строку длины i в пустую стоит i удалений.

```csharp
static int EditDistance(string a, string b)
{
    var dp = new int[a.Length + 1, b.Length + 1];
    for (int i = 0; i <= a.Length; i++) dp[i, 0] = i;
    for (int j = 0; j <= b.Length; j++) dp[0, j] = j;
    for (int i = 1; i <= a.Length; i++)
    for (int j = 1; j <= b.Length; j++)
    {
        int replace = dp[i - 1, j - 1] + (a[i - 1] == b[j - 1] ? 0 : 1);
        int delete = dp[i - 1, j] + 1;
        int insert = dp[i, j - 1] + 1;
        dp[i, j] = Math.Min(replace, Math.Min(delete, insert));
    }
    return dp[a.Length, b.Length];
}
```

`kitten → sitting` — 3. Таблица на единицу больше строк по каждому измерению: нулевая строка и столбец — пустые префиксы, и именно из-за них индексы символов сдвинуты на `- 1`. Время и память O(n · m).

Строка `i` зависит только от строки `i - 1`, поэтому память сжимается до двух строк:

```csharp
static int EditDistanceTwoRows(string a, string b)
{
    var prev = new int[b.Length + 1];
    var cur = new int[b.Length + 1];
    for (int j = 0; j <= b.Length; j++) prev[j] = j;
    for (int i = 1; i <= a.Length; i++)
    {
        cur[0] = i;
        for (int j = 1; j <= b.Length; j++)
        {
            int replace = prev[j - 1] + (a[i - 1] == b[j - 1] ? 0 : 1);
            cur[j] = Math.Min(replace, Math.Min(prev[j] + 1, cur[j - 1] + 1));
        }
        (prev, cur) = (cur, prev);
    }
    return prev[b.Length];
}
```

Память O(m), и обе версии совпали на 500 случайных парах строк. Цена сжатия — нельзя восстановить саму последовательность правок: для неё нужна полная таблица.

## Сложность

Общая формула: **число состояний × стоимость перехода**. Фибоначчи — n состояний по O(1), размен — amount состояний по O(число монет), редакционное расстояние — n · m состояний по O(1). Память — число хранимых состояний, и её часто можно сжать до последних одной-двух строк. Мемоизация добавляет O(глубины) стека и накладные расходы словаря; таблица на массиве обычно быстрее на константу.

Ещё одна классическая DP, алгоритм Кадане для максимальной суммы подмассива, — это DP с состоянием «лучшая сумма, заканчивающаяся в i», сжатым до одной переменной. Она разобрана отдельно в `Максимальная сумма подмассива`.

## Типичные ошибки

- **Состояние не сформулировано** — переход «на глаз», ответ верен на примерах и неверен в общем случае.
- **Неверная база**: `dp[0] = 0` против `dp[0] = 1` в подсчёте способов — разные задачи.
- **Порядок заполнения**, при котором ячейка читается раньше, чем посчитана.
- **Переполнение**: `int.MaxValue + 1` в минимизации, `long` в подсчёте способов и Фибоначчи.
- **Сочетания вместо последовательностей** или наоборот из-за порядка циклов.
- **Мемоизация на большой глубине** — переполнение стека; переходите к таблице.
- **Жадность вместо DP** без доказательства, что жадный выбор оптимален.

## Что стоит ответить на собеседовании

Динамическое программирование применяют, когда у задачи перекрывающиеся подзадачи и оптимальная подструктура: результаты подзадач запоминают, и экспоненциальный перебор становится полиномиальным. Наивный Фибоначчи для n = 40 делает 331 миллион вызовов, с мемоизацией — 79. Два способа: мемоизация сверху вниз — рекурсия с кэшем, проще написать, но глубина стека O(n); таблица снизу вверх — без рекурсии, и память часто сжимается до одной-двух строк.

Сильный ответ показывает метод, а не заученные задачи: сформулировать состояние словами, переход, базу и порядок заполнения; сложность — число состояний на стоимость перехода. Хорошие примеры — размен монет, где жадный алгоритм ошибается на `{1, 3, 4}` и сумме 6, и редакционное расстояние на таблице n × m со сжатием до двух строк. Плюс деталь, которая выдаёт практику: порядок вложенных циклов в подсчёте способов отличает сочетания от последовательностей.
