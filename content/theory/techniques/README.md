# Раздел «Приёмы» — исходники статей

Статьи трека `algorithms` → раздела `techniques`. Метаданные — во
фронтматтере каждого файла, тело — markdown под ним.

## Как залить в базу

Скриптом, а не руками по одной. Импорт берёт один каталог за раз, поэтому
`--dir` обязателен — без него зальётся `csharp-lang`, и сообщения об ошибке
не будет:

```bash
node tools/import-theory.mjs --dry-run --dir content/theory/techniques

node tools/import-theory.mjs \
  --url http://localhost:5103 \
  --email admin@interview.hypex.site \
  --password 'Admin123!' \
  --dir content/theory/techniques

IH_ADMIN_PASSWORD='…' node tools/import-theory.mjs \
  --url https://interview.hypex.site \
  --email admin@hypex.site \
  --dir content/theory/techniques --update --publish
```

Пароль для прода передаётся через переменную окружения, а не флагом:
флаг виден в списке процессов и остаётся в history шелла.

По умолчанию статьи создаются **черновиками** и существующие не трогаются.
`--update` обновляет по slug, `--publish` ставит статус «Опубликована».
Привязки к вопросам импорт не стирает: при обновлении они переносятся как есть.

Метаданные берутся из фронтматтера — `title`, `slug`, `track`, `section`,
`level`, `sortOrder`, `summary`. `readingMinutes` не задаётся: его считает
`AppDbContext.SaveChangesAsync` (200 слов в минуту, минимум 1).

## Файлы и источник правды

**Источник правды — база.** Мелкие правки удобнее делать в админке
(`/admin/theory`). Если правите файл здесь — прогоните импорт с `--update`,
иначе версии разойдутся.

## Чтобы статьи стали видны гостям

Нужны **оба** условия: статус статьи `Published` и трек `IsPublished = true`.
Трек `algorithms` сидер создаёт скрытым — его нужно опубликовать отдельно.

## Раздел написан целиком

Все 6 статей по плану (`THEORY_PLAN.md`) написаны. Весь код из статей
извлекался из markdown, компилировался и прогонялся на тестовых входах
на .NET 10.0.10, Windows 11 x64. Что измерено:

- **размер стека**: 1536 КБ у главного потока, у `new Thread()` и у потока
  пула; `new Thread(work, 64 МБ)` получает 65 536 КБ;
- **глубина до переполнения**: простая рекурсия по списку ~31 700 вызовов
  в Release и ~19 000 в Debug, высота вырожденного дерева ~23 900,
  рекурсивный DFS ~10 600, кадр со `stackalloc` на 64 байта ~7 400;
- **`StackOverflow` не перехватывается**: `catch (Exception)` не сработал,
  процесс завершился с кодом `0xC00000FD`;
- **хвостовая рекурсия**: с настройками по умолчанию упала на ~32 000
  вызовах, с `DOTNET_TieredCompilation=0` прошла 10 млн;
- **`System.Text.Json`**: 64 уровня вложенности разбираются, 65 — нет;
- **`Array.BinarySearch`** на дубликатах вернул средний из равных, а не первый;
- **наивный Фибоначчи** для n = 40 — 331 160 281 вызов против 79 с мемоизацией.

**Размер стека.** Статья `Стек и куча` и статьи `async-await` раньше
писали «1 МБ стека на поток по умолчанию». Замер на .NET 10 под Windows
дал 1,5 МБ для всех трёх видов потоков, там исправлено.

**Грабля замера глубины:** число зависит от размера кадра, режима сборки
и уровня многоуровневой компиляции, поэтому в статьях даны порядки
и конкретная функция, на которой мерили, а не «максимальная глубина в .NET».
