Многие задачи на массивы и строки в лоб решаются двумя вложенными циклами: перебрать все пары и проверить каждую. Это O(n²), и на ста тысячах элементов — десять миллиардов проверок. Приём «два указателя» убирает внутренний цикл: по данным одновременно движутся два индекса, и на каждом шаге по простому правилу сдвигается один из них. Получается один проход за O(n) и O(1) дополнительной памяти.

## Идея

Перебор пар избыточен, когда про часть пар можно сказать заранее, что они не подойдут. Два указателя используют это знание: сдвигая указатель, мы отбрасываем целую группу пар, а не одну.

Классический пример — пара с заданной суммой в **отсортированном** массиве. Ставим `left` на начало, `right` на конец. Если сумма меньше нужной, то `a[left]` в паре с любым элементом левее `right` даст сумму ещё меньше — значит, `a[left]` бесполезен целиком, сдвигаем `left`. Если больше — по той же логике сдвигаем `right`. За один шаг отбрасывается до n пар, поэтому всего шагов не больше n. Полный разбор этой задачи с вариантом на хеш-таблице — в статье `Two sum` следующего раздела.

Ключевое слово — **монотонность**: должно быть понятно, какой указатель двигать, и что позиция, которую он покинул, больше не понадобится. Чаще всего монотонность даёт сортировка, иногда — сама постановка задачи.

## Три разновидности

| Вариант | Как движутся | Задачи |
| --- | --- | --- |
| навстречу | с концов к центру | палиндром, пара с суммой, «контейнер с водой», разворот на месте |
| read/write | `read` идёт всегда, `write` — по условию | удалить дубликаты, сдвинуть нули, отфильтровать на месте |
| по двум последовательностям | по индексу в каждой | слияние, пересечение, сравнение версий |

Отдельно стоит вариант **fast/slow** на связном списке: один указатель шагает на один узел, другой — на два. Так находят середину списка и цикл.

Слияние и пересечение отсортированных массивов разобраны отдельно — в статьях `Слияние отсортированных массивов` и `Пересечение массивов`. Здесь — остальные варианты.

## Как узнать задачу

Сигналы в условии:

- данные **отсортированы** или их можно отсортировать без потери смысла;
- нужна **пара** или тройка элементов с условием на сумму, разность, произведение;
- просят сделать что-то **на месте**, без дополнительной памяти;
- сравниваются символы с двух концов строки;
- связный список и вопрос про середину, цикл, k-й элемент с конца.

Если в условии «непрерывный подмассив» или «подстрока» и интересует то, что между указателями, — это уже скользящее окно, частный случай двух указателей в одном направлении (следующая статья, `Скользящее окно`).

## Навстречу: палиндром

Строка — палиндром, если читается одинаково с обоих концов. Указатели идут навстречу и пропускают всё, кроме букв и цифр:

```csharp
static bool IsPalindrome(string s)
{
    int left = 0, right = s.Length - 1;
    while (left < right)
    {
        if (!char.IsLetterOrDigit(s[left])) { left++; continue; }
        if (!char.IsLetterOrDigit(s[right])) { right--; continue; }
        if (char.ToLowerInvariant(s[left]) != char.ToLowerInvariant(s[right]))
            return false;
        left++;
        right--;
    }
    return true;
}
```

`"A man, a plan, a canal: Panama"` даёт `true`, `"race a car"` — `false`, пустая строка и строка из одних знаков препинания — `true`. Вариант со сравнением строки и её разворота тоже O(n), но тратит O(n) памяти на копию.

## Навстречу: контейнер с водой

Даны высоты стенок; нужно выбрать две так, чтобы между ними поместилось больше всего воды. Площадь — это `min(h[left], h[right]) * (right - left)`.

```csharp
static long MaxArea(int[] h)
{
    int left = 0, right = h.Length - 1;
    long best = 0;
    while (left < right)
    {
        long area = (long)Math.Min(h[left], h[right]) * (right - left);
        best = Math.Max(best, area);
        if (h[left] < h[right]) left++;
        else right--;
    }
    return best;
}
```

Почему двигаем именно низкую стенку: площадь ограничена ею. Если сдвинуть высокую, ширина уменьшится, а высота не вырастет — ответ точно не улучшится. Значит, все пары с текущей низкой стенкой можно отбросить разом. Для `[1, 8, 6, 2, 5, 4, 8, 3, 7]` ответ 49. Умножение в `long` — не украшение: две высоты по 10⁵ и ширина 10⁵ уже не помещаются в `int`.

## Сортировка плюс два указателя: 3Sum

Найти все уникальные тройки с суммой ноль. Перебор троек — O(n³). Сортируем за O(n log n), фиксируем первый элемент и ищем пару навстречу — итого O(n²):

```csharp
static List<int[]> ThreeSum(int[] nums)
{
    var a = (int[])nums.Clone();
    Array.Sort(a);
    var result = new List<int[]>();
    for (int i = 0; i < a.Length - 2; i++)
    {
        if (i > 0 && a[i] == a[i - 1]) continue;
        int left = i + 1, right = a.Length - 1;
        while (left < right)
        {
            long sum = (long)a[i] + a[left] + a[right];
            if (sum < 0) left++;
            else if (sum > 0) right--;
            else
            {
                result.Add([a[i], a[left], a[right]]);
                while (left < right && a[left] == a[left + 1]) left++;
                while (left < right && a[right] == a[right - 1]) right--;
                left++;
                right--;
            }
        }
    }
    return result;
}
```

Для `[-1, 0, 1, 2, -1, -4]` получаем `[-1, -1, 2]` и `[-1, 0, 1]`, для `[0, 0, 0, 0]` — одну тройку. Пропуск одинаковых значений — главная часть задачи: без него тройки дублируются. Копия нужна, чтобы не сортировать входной массив вызывающего.

## Read/write: работа на месте

Указатель `read` проходит каждый элемент, `write` показывает, куда класть следующий «хороший». Всё, что левее `write`, — уже готовый результат.

Удаление дубликатов из отсортированного массива:

```csharp
static int RemoveDuplicates(int[] a)
{
    if (a.Length == 0) return 0;
    int write = 1;
    for (int read = 1; read < a.Length; read++)
        if (a[read] != a[write - 1])
            a[write++] = a[read];
    return write;
}
```

Для `[1, 1, 2, 3, 3, 3, 4]` метод вернёт 4, а массив станет `[1, 2, 3, 4, 3, 3, 4]`: значащий только префикс длиной `write`, хвост — мусор. Это контракт, а не ошибка; по той же схеме работает `List<T>.RemoveAll`.

Сдвиг нулей в конец с сохранением порядка остальных:

```csharp
static void MoveZeroes(int[] a)
{
    int write = 0;
    for (int read = 0; read < a.Length; read++)
    {
        if (a[read] == 0) continue;
        (a[write], a[read]) = (a[read], a[write]);
        write++;
    }
}
```

`[0, 1, 0, 3, 12]` превращается в `[1, 3, 12, 0, 0]`. Обмен через кортеж удобен, но инкремент внутри него опасен: в `(a[write++], a[read]) = (a[read], a[write])` правая часть читает уже увеличенный `write`. На примере выше это случайно сходится, а `[1, 2, 0, 3]` превращается в `[2, 0, 3, 3]`. Поэтому `write++` вынесен в отдельную строку.

## Fast/slow на связном списке

У связного списка нет доступа по индексу, и узнать длину можно только проходом. Два указателя с разной скоростью дают середину за один проход:

```csharp
static ListNode? Middle(ListNode? head)
{
    ListNode? slow = head, fast = head;
    while (fast?.Next is not null)
    {
        slow = slow!.Next;
        fast = fast.Next.Next;
    }
    return slow;
}
```

Когда быстрый дошёл до конца, медленный прошёл половину. На списке из пяти узлов это третий, из четырёх — тоже третий, то есть второй из двух средних; если нужен первый, условие цикла меняют на `fast?.Next?.Next is not null`.

Тот же приём находит цикл (алгоритм Флойда): если цикл есть, быстрый указатель догонит медленный внутри него, если нет — дойдёт до `null`. Достаточно добавить в цикл проверку `ReferenceEquals(slow, fast)`. Память — O(1), против O(n) у решения через `HashSet` посещённых узлов.

## Сложность

Каждый указатель двигается только в одну сторону и проходит данные не больше одного раза, поэтому время O(n), а дополнительная память O(1). Если перед этим нужна сортировка, итог — O(n log n) по времени, и память сортировки: `Array.Sort` сортирует на месте, но копия входа, как в 3Sum, стоит O(n). Подробнее о том, как складываются такие оценки, — в `Big O`.

## Типичные ошибки

- **Условие `left <= right` вместо `left < right`** там, где пара должна состоять из двух разных элементов: элемент сравнивается сам с собой.
- **Двигать не тот указатель.** Правило сдвига надо уметь обосновать: «почему все пары с этим элементом можно отбросить». Если обоснования нет, решение, скорее всего, неверное.
- **Применять приём к неотсортированным данным** в задачах, где монотонность даёт только сортировка, — код работает на примерах из условия и ломается на остальных.
- **Забыть пропуск дубликатов**, когда ответ должен быть уникальным.
- **Переполнение `int`** при сумме или произведении — считайте в `long`.
- **Fast/slow без проверки `fast.Next`** — `NullReferenceException` на списке чётной длины.

## Что стоит ответить на собеседовании

Два указателя — это два индекса, которые двигаются по данным одновременно, и на каждом шаге по обоснованному правилу сдвигается один из них. Приём заменяет перебор пар за O(n²) одним проходом за O(n) с O(1) памяти. Работает, когда есть монотонность: понятно, какой указатель двигать и почему покинутая позиция больше не нужна, — чаще всего её даёт сортировка.

Стоит назвать три варианта с примерами: навстречу (палиндром, пара с суммой в отсортированном массиве, контейнер с водой), read/write для фильтрации на месте (удаление дубликатов, сдвиг нулей) и по двум массивам (слияние, пересечение). Плюс fast/slow на связном списке — середина и цикл по Флойду. Сильный ответ объясняет правило сдвига («низкая стенка ограничивает площадь, поэтому все пары с ней отбрасываются») и упоминает, что сортировка добавляет O(n log n) и меняет входной массив.
