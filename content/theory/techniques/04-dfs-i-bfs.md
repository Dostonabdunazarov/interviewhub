Почти любая задача на граф, дерево или сетку сводится к обходу: начать с вершины и посетить всё, что из неё достижимо. Обходов два — в ширину (BFS) и в глубину (DFS). Оба проходят граф за O(V + E), но в разном порядке, и из порядка следует всё остальное: какой из них ищет кратчайший путь, а какой умеет топологическую сортировку. Как графы хранить в памяти — список смежности, матрица, сетка, — разобрано в `Деревья и графы`; здесь граф — это `List<int>[]`, где `graph[v]` — соседи вершины `v`.

## Идея: один алгоритм, две структуры

Итеративный обход устроен одинаково: есть множество найденных, но ещё не обработанных вершин; берём из него одну, обрабатываем, добавляем её непосещённых соседей. Разница только в том, **какую** вершину брать следующей:

- **самую раннюю** — очередь (FIFO), получается BFS: обход «волнами», сначала все вершины на расстоянии 1, потом 2 и так далее;
- **самую свежую** — стек (LIFO) или рекурсия, получается DFS: идём по одной ветке до упора, потом откатываемся.

Если в итеративном BFS заменить `Queue<T>` на `Stack<T>`, получится вариант DFS. Сами структуры разобраны в статье `Стек и очередь`.

## Как узнать задачу

BFS — когда важно **расстояние**: «минимальное число ходов», «кратчайший путь» при одинаковой цене шага, «ближайший», «на каком уровне». Вершинами могут быть и состояния: слово в цепочке преобразований, позиция на доске.

DFS — когда нужно **исследовать всё** или **перебрать варианты**: компоненты связности, есть ли путь вообще, цикл в зависимостях, порядок сборки, все подмножества и перестановки, агрегаты по поддеревьям (высота, сумма, размер).

Если подходят оба, как в подсчёте островов, берут тот, что проще написать.

## BFS: кратчайший путь

```csharp
static List<int>? ShortestPath(List<int>[] graph, int start, int target)
{
    var parent = new int[graph.Length];
    Array.Fill(parent, -1);
    parent[start] = start;
    var queue = new Queue<int>();
    queue.Enqueue(start);

    while (queue.Count > 0)
    {
        int v = queue.Dequeue();
        if (v == target) return BuildPath(parent, target);
        foreach (int next in graph[v])
        {
            if (parent[next] != -1) continue;
            parent[next] = v;
            queue.Enqueue(next);
        }
    }
    return null;
}

static List<int> BuildPath(int[] parent, int target)
{
    var path = new List<int> { target };
    for (int v = target; parent[v] != v; v = parent[v])
        path.Add(parent[v]);
    path.Reverse();
    return path;
}
```

Массив `parent` работает сразу как `visited` и как способ восстановить путь: от цели идём по родителям к старту и разворачиваем. Если старт совпадает с целью, ответ — путь из одной вершины; если цель недостижима — `null`.

**Почему путь кратчайший.** Очередь гарантирует, что все вершины на расстоянии k обрабатываются раньше любой вершины на расстоянии k + 1. Значит, когда вершина обнаружена впервые, путь до неё уже минимален — короче позже не появится. Это верно только для **невзвешенного** графа. С весами BFS минимизирует число рёбер, а не их сумму; там нужен алгоритм Дейкстры — тот же обход, но с `PriorityQueue<TElement, TPriority>` вместо очереди.

**Вершину помечают при добавлении, а не при извлечении.** Если помечать при `Dequeue`, одна вершина успевает попасть в очередь от каждого соседа, и в плотном графе это O(V²) лишних операций.

## BFS по уровням

Когда нужен номер уровня — обход дерева по уровням, «правый вид», среднее по уровню, — фиксируем размер очереди перед обработкой уровня:

```csharp
static List<List<int>> LevelOrder(TreeNode? root)
{
    var levels = new List<List<int>>();
    if (root is null) return levels;
    var queue = new Queue<TreeNode>();
    queue.Enqueue(root);
    while (queue.Count > 0)
    {
        int size = queue.Count;
        var level = new List<int>(size);
        for (int i = 0; i < size; i++)
        {
            var node = queue.Dequeue();
            level.Add(node.Value);
            if (node.Left is not null) queue.Enqueue(node.Left);
            if (node.Right is not null) queue.Enqueue(node.Right);
        }
        levels.Add(level);
    }
    return levels;
}
```

Для дерева `3 → (9, 20 → (15, 7))` получаем `[3]`, `[9, 20]`, `[15, 7]`. В дереве `visited` не нужен: циклов нет, к каждому узлу ведёт один путь.

## DFS: рекурсивный и итеративный

```csharp
static void Dfs(List<int>[] graph, int v, bool[] visited, List<int> order)
{
    visited[v] = true;
    order.Add(v);
    foreach (int next in graph[v])
        if (!visited[next])
            Dfs(graph, next, visited, order);
}
```

Запись короткая и близка к определению, но глубина рекурсии равна длине самого длинного пути обхода. На графе-цепочке это V. Замер на .NET 10 (Windows, x64, Release): рекурсивный DFS в такой форме падает примерно на **10 600** вершинах цепочки — процесс завершается с `Stack overflow`, и `catch` не помогает. Почему так и сколько это для других функций — в следующей статье, `Рекурсия и переполнение стека`.

Итеративная версия держит стек в куче и ограничена только памятью:

```csharp
static List<int> DfsIterative(List<int>[] graph, int start)
{
    var visited = new bool[graph.Length];
    var order = new List<int>();
    var stack = new Stack<int>();
    stack.Push(start);
    while (stack.Count > 0)
    {
        int v = stack.Pop();
        if (visited[v]) continue;
        visited[v] = true;
        order.Add(v);
        for (int i = graph[v].Count - 1; i >= 0; i--)
            if (!visited[graph[v][i]])
                stack.Push(graph[v][i]);
    }
    return order;
}
```

Здесь вершину помечают при извлечении: одна вершина может лежать в стеке несколько раз, и повтор отсекается `continue`. Соседи кладутся в обратном порядке, чтобы порядок посещения совпал с рекурсивным.

## Pre-order и post-order

Главное, что DFS даёт помимо обхода, — два момента для каждой вершины: **вход** (pre-order, до потомков) и **выход** (post-order, после них). Pre-order нужен для сериализации и копирования дерева, in-order в дереве поиска даёт ключи по возрастанию, post-order — размеры поддеревьев и **топологическую сортировку**.

## Пример: топологическая сортировка и цикл

Порядок сборки проектов, применения миграций, запуска сервисов: `deps[v]` — от чего зависит `v`. Вершина добавляется в ответ на выходе, когда все её зависимости уже добавлены. Цикл обнаруживается тем же проходом — через три состояния:

```csharp
static List<int>? TopoSort(List<int>[] deps)
{
    var state = new byte[deps.Length];
    var order = new List<int>(deps.Length);

    bool Visit(int v)
    {
        if (state[v] == 1) return false;
        if (state[v] == 2) return true;
        state[v] = 1;
        foreach (int d in deps[v])
            if (!Visit(d)) return false;
        state[v] = 2;
        order.Add(v);
        return true;
    }

    for (int v = 0; v < deps.Length; v++)
        if (!Visit(v)) return null;
    return order;
}
```

Состояние 0 — не посещена, 1 — на текущем пути, 2 — готова. Встретить вершину в состоянии 1 значит вернуться в собственный путь: это цикл, и метод вернёт `null`. Двух состояний для ориентированного графа мало — вершина, уже обработанная через другую ветку, циклом не является. Для зависимостей `0 → {1, 2}`, `1 → 3`, `2 → 3` порядок — `[3, 1, 2, 0]`, для `0 → 1 → 2 → 0` — `null`. Время O(V + E). Альтернатива без рекурсии — алгоритм Кана: BFS по вершинам с нулевой входящей степенью.

## Пример: острова на сетке

Сетка — тоже граф: клетка — вершина, соседи — четыре клетки вокруг, проверенные на выход за границы. Число островов из единиц считается так: идём по всем клеткам, на каждой непосещённой суше увеличиваем счётчик и заливаем весь остров обходом, помечая клетки. Задачу принято решать рекурсивным DFS, но заливку надёжнее делать BFS с очередью или итеративным DFS: на сетке 1000 × 1000, целиком из суши, рекурсия ушла бы на глубину в сотни тысяч и уронила процесс, а версия с очередью с ней справилась. Время и память — O(rows · cols).

## Сложность

Оба обхода работают за O(V + E): каждая вершина обрабатывается один раз, каждое ребро просматривается один раз (в неориентированном графе — дважды). Память — до O(V) у обоих, но BFS держит ширину уровня, а DFS — глубину, и на практике решает форма графа. В полном бинарном дереве очередь BFS в пике держит последний уровень — около n/2 узлов, а стек DFS — log n. На цепочке наоборот: BFS держит одну вершину, DFS — всю глубину.

## Типичные ошибки

- **Нет `visited`** в графе с циклами — бесконечный обход.
- **Пометка при извлечении в BFS** — вершины дублируются в очереди.
- **BFS на взвешенном графе** как поиск кратчайшего пути.
- **DFS как поиск кратчайшего пути** — первый найденный путь может быть сколь угодно длинным.
- **Рекурсивный DFS на больших входах** — `StackOverflow`, который не перехватывается.
- **Нет проверки границ** на сетке до обращения к соседу.
- **Обход только из вершины 0** там, где граф несвязный: компоненты, топосортировка и поиск циклов требуют внешнего цикла по всем вершинам.

## Что стоит ответить на собеседовании

BFS и DFS обходят всё достижимое за O(V + E) и отличаются тем, какую вершину брать следующей: BFS — из очереди, волнами по расстоянию, поэтому в невзвешенном графе первым находит кратчайший путь; DFS — из стека или рекурсии, вглубь по ветке, и даёт pre- и post-order, на которых строятся топологическая сортировка, поиск циклов (три цвета) и перебор с возвратом.

Стоит назвать детали, которые отличают рабочий код: в BFS вершину помечают при добавлении в очередь, путь восстанавливают через `parent`, для весов нужен Дейкстра. Про память: BFS держит ширину уровня, DFS — глубину. И про .NET: рекурсивный DFS на цепочке примерно из десяти тысяч вершин переполняет стек и роняет процесс без шанса на `catch`, поэтому для входных данных извне обход пишут итеративно.
