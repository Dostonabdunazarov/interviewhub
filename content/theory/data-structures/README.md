# Раздел «Структуры данных» — исходники статей

Статьи трека `Алгоритмы` (`algorithms`) → раздела `data-structures`.
Метаданные — во фронтматтере каждого файла, тело — markdown под ним.

## Как залить в базу

Скриптом, а не руками по одной:

```bash
node tools/import-theory.mjs --dry-run --dir content/theory/data-structures

node tools/import-theory.mjs \
  --url http://localhost:5103 \
  --email admin@interview.hypex.site \
  --password 'Admin123!' \
  --dir content/theory/data-structures

IH_ADMIN_PASSWORD='…' node tools/import-theory.mjs \
  --url https://interview.hypex.site \
  --email admin@hypex.site \
  --dir content/theory/data-structures
```

Первая команда показывает, что будет сделано, вторая заливает локально,
третья — в прод. Пароль для прода передаётся через переменную окружения,
а не флагом: флаг виден в списке процессов и остаётся в history шелла.

**Импорт берёт один каталог за раз** и по умолчанию читает `csharp-lang`,
поэтому `--dir` обязателен — без него этот раздел просто не зальётся,
и сообщения об ошибке не будет.

По умолчанию статьи создаются **черновиками** и существующие не трогаются.
`--update` обновляет по slug, `--publish` ставит статус «Опубликована».
Привязки к вопросам импорт не стирает: при обновлении они переносятся как есть.

Метаданные берутся из фронтматтера — `title`, `slug`, `track`, `section`,
`level`, `sortOrder`, `summary`. `readingMinutes` не задаётся: его считает
`AppDbContext.SaveChangesAsync` (200 слов в минуту, минимум 1).

## Связь с разделом «Коллекции»

Раздел `collections` трека `dotnet-backend` уже разбирает устройство
`List<T>`, `Dictionary`, `HashSet<T>` и `LinkedList<T>` в .NET. Статьи здесь
смотрят на те же структуры со стороны алгоритмов — идея, сложности,
компромиссы, классические задачи — и ссылаются на статьи коллекций
по заголовку, а не пересказывают их.

## Чтобы статьи стали видны гостям

Нужны **оба** условия: статус статьи `Published` и трек `IsPublished = true`.
Трек `algorithms` включается после публикации первого раздела, `complexity`
(подробности — в его README). Если этот раздел публикуется раньше,
трек нужно включить переключателем «виден» в админке.

## Раздел написан целиком

Все 5 статей по плану (`THEORY_PLAN.md`) написаны. Источник материала —
ответы категории `algorithms` из `content/questions/algorithms.md`.
Числа измерены на .NET 10.0.10 (SDK 10.0.302), Windows 11, x64, Release;
код замеров — `.claude/tempfiles/theory-algo/Lab`, все фрагменты кода
из статей собраны и проверены в `.claude/tempfiles/theory-algo/Snippets`.
Что проверялось:

- **локальность**: сумма миллиона `int` — массив 0,60 мс, список из узлов,
  созданных подряд, 1,86 мс, тех же узлов в случайном порядке 102,6 мс;
  узел `{ int; Node? }` весит 32 байта;
- **очередь**: положить и забрать 100 000 элементов — `Queue<T>` 0,63 мс,
  `List<T>` с `RemoveAt(0)` 364 мс;
- **открытая адресация** с линейным пробированием: среднее число проверок
  при заполнении 50 / 75 / 90 / 95% — 1,5 / 2,5 / 5,4 / 10,4 для найденного
  ключа и 2,5 / 8,5 / 50 / 199 для отсутствующего, совпадает с оценкой Кнута;
- **память множеств** на миллионе `int` без ёмкости: `HashSet<int>` 22,3 байта
  на элемент, `Dictionary<int, bool>` и `Dictionary<int, int>` по 27,9;
- **подсчёт частот** миллиона элементов: `ContainsKey` + индексатор 9,8 мс,
  `GetValueOrDefault` 7,8, `CollectionsMarshal.GetValueRefOrAddDefault` 3,5,
  `CountBy` 6,5, `GroupBy` 14,5 мс и 8,5 МБ, массив счётчиков 1,0;
  `ContainsValue` на тысяче элементов в 76 раз медленнее `ContainsKey`;
- **выродившееся дерево поиска**: высота 10 000 на отсортированных ключах
  против 34 на перемешанных;
- **граф** на 10 000 вершин и 50 000 рёбер: матрица `bool` 100 МБ,
  списки смежности 1,2 МБ, `Dictionary<int, List<int>>` 1,6 МБ.

**Грабля замера:** время поиска в маленьком дереве (1 000 узлов) скакало
между прогонами в полтора раза — первые вызовы попадают на код Tier 0.
В статью попали только высоты и замер на 10 000 узлов.

Обходы DFS и BFS, бинарный поиск и два указателя здесь только упоминаются —
они раскрываются в разделе `techniques`; Two Sum, top K, скобки и слияние
отсортированных массивов — в `drills`.
