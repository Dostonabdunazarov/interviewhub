Массив и связный список — две противоположные идеи хранения последовательности. Массив кладёт элементы в память подряд и за это получает мгновенный доступ по индексу. Список раскладывает элементы по отдельным узлам, связанным ссылками, и за это получает дешёвую вставку в любом месте. Почти все остальные структуры данных построены на одной из этих двух идей, поэтому их стоит понимать до уровня «почему», а не только «какая сложность». Как это реализовано в .NET — `List<T>` и `LinkedList<T>` — разобрано в разделе «Коллекции»; здесь взгляд со стороны алгоритмов.

## Массив: непрерывный блок памяти

Массив — это участок памяти, в котором элементы одного размера лежат вплотную. Адрес `i`-го элемента вычисляется формулой: начало массива плюс `i × размер элемента`. Отсюда доступ по индексу за O(1) — никакого поиска, одна арифметическая операция.

У этой простоты две цены. Размер фиксирован при создании — чтобы «увеличить» массив, нужно выделить новый и скопировать. И вставка в середину требует сдвинуть все последующие элементы:

```csharp
static void InsertAt(int[] items, int count, int index, int value)
{
    Array.Copy(items, index, items, index + 1, count - index);
    items[index] = value;
}
```

Метод предполагает, что в массиве есть свободное место после `count` элементов. Сдвиг хвоста — O(n − index), в худшем случае O(n).

**Динамический массив** снимает ограничение размера: когда место кончается, выделяется массив вдвое больше и всё копируется. Добавление в конец становится O(1) амортизированно (подробно — в статье `Big O`, реализация в .NET — `Array vs List<T>`). Это самая используемая структура данных в любом языке.

## Связный список: узлы и ссылки

Элемент односвязного списка — отдельный узел со значением и ссылкой на следующий:

```csharp
sealed class Node(int value)
{
    public int Value = value;
    public Node? Next;
}
```

Список хранит только ссылку на первый узел. Чтобы добраться до `i`-го элемента, нужно пройти `i` ссылок — O(n). Зато вставка после известного узла — это перестановка двух ссылок, O(1), и остальные элементы не трогаются:

```csharp
static void InsertAfter(Node node, int value)
{
    var inserted = new Node(value) { Next = node.Next };
    node.Next = inserted;
}
```

**Двусвязный** список хранит в узле ещё и ссылку на предыдущий. Это позволяет удалить узел за O(1), имея только его самого, и идти в обе стороны — ценой ещё одной ссылки на каждый элемент. В реализациях часто используют **фиктивный узел** (sentinel): голова и хвост ссылаются на него, и вставка в пустой список, в начало и в конец перестают быть особыми случаями.

## Сравнение операций

| Операция | Массив | Динамический массив | Связный список |
| --- | --- | --- | --- |
| доступ по индексу | O(1) | O(1) | O(n) |
| поиск по значению | O(n) | O(n) | O(n) |
| вставка в начало | — | O(n) | O(1) |
| вставка в конец | — | O(1) амортизированно | O(1) с хвостовой ссылкой |
| вставка после известного места | O(n) | O(n) | O(1) |
| удаление известного узла | O(n) | O(n) | O(1) в двусвязном |
| лишняя память на элемент | нет | запас ёмкости | ссылки и заголовок узла |

Ключевая оговорка к колонке списка — **«известного»**. Если узел сначала нужно найти, поиск стоит O(n), и выигрыш от дешёвой вставки исчезает.

## Почему таблица врёт: кэш процессора

По таблице проход по массиву и проход по списку одинаковы — O(n). На практике разница огромна, и причина не в алгоритме, а в железе. Процессор читает память не байтами, а строками кэша по 64 байта и заранее подгружает следующие адреса, если видит последовательный доступ. Массив идеально под это подходит: один промах кэша приносит сразу 16 `int`. Узлы списка лежат где придётся, и каждый переход по ссылке рискует промахнуться.

Замер на .NET 10.0.10, сумма миллиона `int`:

```
массив                                       0,60 мс
список, узлы созданы подряд                  1,86 мс
список, узлы связаны в случайном порядке   102,58 мс
```

Узлы, созданные подряд, сборщик мусора разместил почти последовательно, и список проиграл массиву только втрое. Когда тот же миллион узлов связан в случайном порядке — как бывает после долгой жизни списка со вставками и удалениями, — проход стал в 170 раз медленнее массива при той же O(n).

Вторая цена списка — память. Узел из примера выше весит 32 байта (заголовок объекта, `int` и ссылка), то есть миллион элементов — 32 МБ против 4 МБ у массива `int`. И каждый узел — отдельная аллокация, работа для сборщика мусора.

Отсюда практическое правило: связный список выигрывает, только когда ссылки на узлы хранятся отдельно и вставок-удалений по ним действительно много. Канонический случай — LRU-кэш, где словарь указывает прямо на узлы; он разобран в статье `LinkedList<T>`.

## Где связный список незаменим

**Неизменяемые списки.** Односвязный список можно «изменять», не трогая существующие узлы: добавление в голову создаёт один новый узел, который ссылается на старый список. Две версии делят общий хвост, и копирования нет. На этом построены списки в функциональных языках и `ImmutableStack<T>` в .NET.

**Структуры поверх списка.** Стек на односвязном списке, очередь со ссылкой на хвост, цепочки в хеш-таблице, списки смежности в графе — везде, где нужна последовательность переменной длины без требований к индексу.

**Слияние и разрезание.** Два списка соединяются перестановкой одной ссылки за O(1); массивы пришлось бы копировать.

## Классические задачи

Задачи на связные списки любят на собеседованиях за то, что они проверяют аккуратность работы со ссылками. Самая частая — развернуть односвязный список за O(n) времени и O(1) памяти:

```csharp
static Node? Reverse(Node? head)
{
    Node? previous = null;
    while (head is not null)
    {
        var next = head.Next;
        head.Next = previous;
        previous = head;
        head = next;
    }
    return previous;
}
```

Порядок присваиваний здесь и есть вся задача: сначала запомнить `next`, потом развернуть ссылку, потом сдвинуться. Перепутав их, легко потерять остаток списка.

Ещё три классики — найти середину списка, обнаружить цикл (алгоритм Флойда, «черепаха и заяц») и найти `k`-й элемент с конца. Все они решаются двумя указателями, движущимися с разной скоростью или с отставанием, и разобраны в статье про два указателя в разделе «Приёмы». Слияние двух отсортированных последовательностей — в разделе «Типовые задачи».

Общий совет для задач на списки: рисовать узлы и стрелки на каждом шаге и отдельно проверять пустой список, список из одного элемента и операции на голове.

## Что стоит ответить на собеседовании

Массив хранит элементы подряд, поэтому доступ по индексу — O(1) адресной арифметикой, но вставка в середину сдвигает хвост за O(n), а рост требует копирования; динамический массив делает добавление в конец амортизированно O(1). Связный список хранит элементы в узлах со ссылками: доступ по индексу — O(n), зато вставка и удаление по известному узлу — O(1).

Сильный ответ добавит, что асимптотика скрывает главное — локальность. На .NET 10 сумма миллиона элементов массива занимает 0,6 мс, а списка с узлами в случайном порядке — около 100 мс при той же O(n), и узел стоит 32 байта против 4 у `int` в массиве. Поэтому список выбирают, только когда на руках есть ссылки на узлы (LRU-кэш) или нужна неизменяемая структура с общим хвостом. И уверенно напишет разворот списка тремя ссылками — эту задачу дают чаще остальных.
