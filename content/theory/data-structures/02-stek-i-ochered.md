Стек и очередь — это не столько структуры данных, сколько **договорённости о порядке**: стек отдаёт последний положенный элемент, очередь — первый. Реализовать их можно по-разному, и вопрос «как бы вы реализовали» на собеседовании проверяет как раз умение отделить интерфейс от устройства. В .NET готовы `Stack<T>` и `Queue<T>`, но полезно понимать, что у них внутри и почему это устроено именно так.

## Абстрактный тип против реализации

| | Стек (LIFO) | Очередь (FIFO) |
| --- | --- | --- |
| добавить | `Push` — на вершину | `Enqueue` — в хвост |
| извлечь | `Pop` — с вершины | `Dequeue` — из головы |
| посмотреть | `Peek` — вершину | `Peek` — голову |
| сложность всех трёх | O(1) | O(1) |
| поиск произвольного элемента | O(n) | O(n) |

Контракт требует только этих операций, и любая реализация, дающая их за O(1), подходит. Две естественные основы — массив и связный список.

## Стек на массиве

Стек ложится на динамический массив без всяких хитростей: вершина — это последний занятый элемент, и все операции происходят в конце, где массиву ничего не нужно сдвигать.

```csharp
sealed class ArrayStack<T>
{
    private T[] _items = new T[4];
    private int _count;

    public int Count => _count;

    public void Push(T item)
    {
        if (_count == _items.Length)
            Array.Resize(ref _items, _items.Length * 2);
        _items[_count++] = item;
    }

    public T Pop()
    {
        if (_count == 0) throw new InvalidOperationException("Стек пуст");
        var item = _items[--_count];
        _items[_count] = default!;
        return item;
    }
}
```

`Push` — O(1) амортизированно из-за удвоения, `Pop` — честная O(1). Обнуление освобождённой ячейки нужно для ссылочных типов: иначе массив продолжит держать ссылку на снятый объект, и сборщик мусора его не соберёт.

Стек на односвязном списке тоже даёт O(1) — добавление и удаление в голове, — но платит аллокацией на каждый элемент и худшей локальностью (см. `Массив и связный список`). Поэтому `Stack<T>` в .NET устроен на массиве.

## Очередь: почему не List.RemoveAt(0)

Наивная очередь на динамическом массиве — добавлять в конец и забирать из начала. Проблема в том, что удаление первого элемента сдвигает все остальные, и каждый `Dequeue` становится O(n). Замер на .NET 10.0.10 — положить `n` элементов и забрать все:

| n | `Queue<T>` | `List<T>` с `RemoveAt(0)` |
| --- | --- | --- |
| 10 000 | 0,09 мс | 4,2 мс |
| 100 000 | 0,63 мс | 364 мс |

Квадратичная очередь на ста тысячах элементов в 580 раз медленнее.

Правильное решение — **кольцевой буфер**: массив плюс индекс головы и число элементов. При извлечении элементы не сдвигаются, двигается только голова, а индексы «заворачиваются» на начало массива через остаток от деления:

```csharp
sealed class RingQueue<T>
{
    private T[] _items = new T[4];
    private int _head;
    private int _count;

    public int Count => _count;

    public void Enqueue(T item)
    {
        if (_count == _items.Length) Grow();
        _items[(_head + _count) % _items.Length] = item;
        _count++;
    }

    public T Dequeue()
    {
        if (_count == 0) throw new InvalidOperationException("Очередь пуста");
        var item = _items[_head];
        _items[_head] = default!;
        _head = (_head + 1) % _items.Length;
        _count--;
        return item;
    }

    private void Grow()
    {
        var bigger = new T[_items.Length * 2];
        for (int i = 0; i < _count; i++)
            bigger[i] = _items[(_head + i) % _items.Length];
        _items = bigger;
        _head = 0;
    }
}
```

При росте элементы копируются в новый массив по порядку, начиная с головы, — просто скопировать массив целиком нельзя, хвост мог «завернуть» в его начало. Так устроен и `Queue<T>`.

## Очередь из двух стеков

Классический вопрос: реализовать очередь, имея только стеки. Решение — входной стек для `Enqueue` и выходной для `Dequeue`; когда выходной пуст, в него перекладывается весь входной, и порядок разворачивается:

```csharp
sealed class TwoStackQueue<T>
{
    private readonly Stack<T> _in = new();
    private readonly Stack<T> _out = new();

    public int Count => _in.Count + _out.Count;

    public void Enqueue(T item) => _in.Push(item);

    public T Dequeue()
    {
        if (_out.Count == 0)
            while (_in.Count > 0)
                _out.Push(_in.Pop());
        return _out.Pop();
    }
}
```

Отдельный `Dequeue` может стоить O(n), но каждый элемент перекладывается ровно один раз за свою жизнь, поэтому амортизированно все операции O(1). Это хороший повод показать на собеседовании, что вы понимаете амортизированный анализ, а не только помните ответ.

## Дек и очередь с приоритетом

**Дек** (deque) — очередь с двумя концами: добавлять и забирать можно и с головы, и с хвоста. Реализуется тем же кольцевым буфером. Отдельного `Deque<T>` в .NET нет; в задачах вместо него берут `LinkedList<T>` или пишут свой буфер.

**Очередь с приоритетом** отдаёт не первый пришедший, а минимальный элемент. Это уже не последовательность, а куча — дерево, уложенное в массив, — и её операции стоят O(log n). Она разобрана в статье `Деревья и графы`, а в .NET это `PriorityQueue<TElement, TPriority>`.

## Где встречается стек

- **Стек вызовов.** Каждый вызов метода кладёт кадр, возврат — снимает. Любую рекурсию можно переписать на явный `Stack<T>`, и это стандартный способ уйти от переполнения стека (раздел «Приёмы»).
- **Проверка скобок и разбор выражений** — открывающая скобка кладётся, закрывающая сверяется с вершиной. Задача целиком разобрана в разделе «Типовые задачи».
- **Отмена действий** — история изменений, где последнее отменяется первым.
- **Обход в глубину** — итеративный DFS держит путь в стеке.

Отдельный приём — **монотонный стек**: в стеке хранятся индексы, значения по которым идут по убыванию. Он решает за O(n) задачи вида «для каждого элемента найти следующий больший»:

```csharp
static int[] NextGreater(int[] values)
{
    var result = new int[values.Length];
    Array.Fill(result, -1);
    var pending = new Stack<int>();
    for (int i = 0; i < values.Length; i++)
    {
        while (pending.Count > 0 && values[pending.Peek()] < values[i])
            result[pending.Pop()] = values[i];
        pending.Push(i);
    }
    return result;
}
```

Для `[2, 1, 5, 3, 6]` результат `[5, 5, 6, 6, -1]`. Каждый индекс кладётся и снимается не больше одного раза, поэтому вложенный `while` не делает алгоритм квадратичным.

## Где встречается очередь

- **Обход в ширину** — очередь гарантирует, что вершины обрабатываются по уровням, и отсюда кратчайший путь в невзвешенном графе (раздел «Приёмы»).
- **Буферы и конвейеры** — задачи между производителем и потребителем; в многопоточном коде это `ConcurrentQueue<T>` и `Channel<T>` (см. `Channel<T>`).
- **Скользящее окно событий** — последние `k` запросов для ограничения частоты.
- **Брокеры сообщений** — та же идея на уровне системы.

## Детали API в .NET

`Pop` и `Dequeue` на пустой коллекции бросают `InvalidOperationException`, поэтому в коде без гарантий удобнее `TryPop` и `TryDequeue`. Перечисление `Stack<T>` идёт от вершины к низу: стек из `1, 2, 3` перечисляется как `3, 2, 1`. Обе коллекции не потокобезопасны.

## Что стоит ответить на собеседовании

Стек — LIFO, очередь — FIFO, все основные операции O(1). Стек естественно ложится на массив: операции идут в его конце. Очередь на массиве требует кольцевого буфера с индексом головы — наивный `List.RemoveAt(0)` делает каждое извлечение O(n), и на 100 000 элементах это 364 мс против 0,6 мс у `Queue<T>`.

Сильный ответ реализует очередь из двух стеков и объяснит, почему она амортизированно O(1): каждый элемент перекладывается ровно один раз. И назовёт применения: стек — вызовы методов, скобки, DFS и монотонный стек для «следующего большего» за O(n); очередь — BFS, буферы между производителем и потребителем, окно последних событий.
