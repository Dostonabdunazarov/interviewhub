Массивы, списки и хеш-таблицы хранят последовательности и наборы. Деревья и графы хранят **связи**: иерархию категорий, зависимости сервисов, дороги между городами, друзей в соцсети. На собеседовании от middle-разработчика обычно ждут уверенного владения терминами, понимания, зачем нужна балансировка, умения выбрать представление графа — и обхода, которому посвящена статья про DFS и BFS в разделе «Приёмы». Замеры сделаны на .NET 10.0.10.

## Термины

**Дерево** — связный граф без циклов. Из этого следует, что в дереве из `n` вершин ровно `n − 1` рёбер и между любыми двумя вершинами ровно один путь. У корневого дерева выделен **корень**, у каждой вершины, кроме корня, есть **родитель**, вершины без детей — **листья**. **Глубина** вершины — расстояние до корня, **высота** дерева — максимальная глубина.

**Двоичное дерево** — у каждой вершины не больше двух детей, левый и правый. Почти все алгоритмы над деревьями оцениваются через высоту `h`: у сбалансированного дерева она O(log n), у выродившегося — O(n).

## Двоичное дерево поиска

В двоичном дереве поиска (BST) для каждой вершины все ключи левого поддерева меньше её ключа, а все ключи правого — больше. Поиск идёт от корня и на каждом шаге отбрасывает одно из поддеревьев:

```csharp
sealed class BinarySearchTree
{
    private sealed class TreeNode(int key)
    {
        public int Key = key;
        public TreeNode? Left, Right;
    }

    private TreeNode? _root;

    public void Insert(int key)
    {
        if (_root is null) { _root = new TreeNode(key); return; }
        var current = _root;
        while (true)
        {
            if (key == current.Key) return;
            ref var next = ref key < current.Key ? ref current.Left : ref current.Right;
            if (next is null) { next = new TreeNode(key); return; }
            current = next;
        }
    }

    public bool Contains(int key)
    {
        var current = _root;
        while (current is not null)
        {
            if (key == current.Key) return true;
            current = key < current.Key ? current.Left : current.Right;
        }
        return false;
    }
}
```

Поиск, вставка и удаление стоят O(h). Обход в порядке «левое поддерево — вершина — правое» (in-order) выдаёт ключи по возрастанию: это и есть главное преимущество дерева перед хеш-таблицей — порядок, минимум, максимум, ближайший ключ и диапазоны.

## Почему деревья балансируют

Высота BST зависит от порядка вставки. Если ключи приходят отсортированными, каждый новый становится правым ребёнком предыдущего, и дерево вырождается в связный список. Замер высоты для дерева из кода выше:

| n | Высота, ключи по порядку | Высота, ключи вперемешку | log₂ n |
| --- | --- | --- | --- |
| 1 000 | 1 000 | 20 | 10 |
| 10 000 | 10 000 | 34 | 13,3 |

На выродившемся дереве из 10 000 ключей тысяча поисков заняла 4,7 мс, на случайном — меньше 0,2 мс, разница в десятки раз. А отсортированные ключи — не экзотика: идентификаторы, даты и номера заказов приходят именно так.

**Сбалансированные деревья** — красно-чёрное, AVL — после каждой вставки и удаления выполняют повороты, которые гарантируют высоту O(log n) для любого порядка вставки. Реализовывать их на собеседовании не просят, но знать, что `SortedSet<T>` и `SortedDictionary<TKey, TValue>` в .NET — красно-чёрные деревья с O(log n) на операцию, стоит:

```csharp
var ids = new SortedSet<int>(Enumerable.Range(0, 100));
var window = ids.GetViewBetween(10, 15);
```

`GetViewBetween` возвращает диапазон 10…15 без перебора всего набора — хеш-таблица так не умеет.

На диске живёт родственник — **B-дерево**: у вершины сотни детей, и даже на миллиарде записей высота — три-четыре уровня. На нём построены индексы баз данных (см. `Индексы: B-tree, GIN, BRIN`).

## Куча и очередь с приоритетом

**Двоичная куча** — двоичное дерево, где каждая вершина не больше своих детей (min-куча). Минимум всегда в корне, а порядок между братьями не важен — это слабее дерева поиска и дешевле в поддержке.

Кучу хранят не узлами, а **в массиве**: дети вершины `i` лежат в ячейках `2i + 1` и `2i + 2`, родитель — в `(i − 1) / 2`. Ссылок нет вовсе, локальность отличная. Вставка кладёт элемент в конец и «всплывает» его вверх, извлечение минимума ставит последний элемент в корень и «топит» вниз — обе операции O(log n). Построить кучу из готового массива можно за O(n).

| Операция | Куча | Сортированный массив | Сбалансированное дерево |
| --- | --- | --- | --- |
| посмотреть минимум | O(1) | O(1) | O(log n) |
| извлечь минимум | O(log n) | O(n) | O(log n) |
| вставка | O(log n) | O(n) | O(log n) |
| поиск произвольного | O(n) | O(log n) | O(log n) |

В .NET куча — это `PriorityQueue<TElement, TPriority>`; у вершины там не два ребёнка, а четыре, но идея та же:

```csharp
var jobs = new PriorityQueue<string, int>();
jobs.Enqueue("отчёт", 5);
jobs.Enqueue("алерт", 1);
jobs.Enqueue("рассылка", 3);
while (jobs.TryDequeue(out var job, out _))
    Console.WriteLine(job);
```

Выведет «алерт», «рассылка», «отчёт» — по возрастанию приоритета. Куча нужна в планировщиках, алгоритме Дейкстры, слиянии `k` отсортированных потоков и задаче «top K элементов», которая разобрана в разделе «Типовые задачи».

## Префиксное дерево

**Trie** хранит строки по символам: каждое ребро — символ, путь от корня — префикс. Поиск слова или префикса стоит O(длины строки) и не зависит от числа слов:

```csharp
sealed class Trie
{
    private sealed class TrieNode
    {
        public readonly Dictionary<char, TrieNode> Children = [];
        public bool IsWord;
        public int WordsBelow;
    }

    private readonly TrieNode _root = new();

    public void Add(string word)
    {
        if (Contains(word)) return;
        var node = _root;
        foreach (var ch in word)
        {
            if (!node.Children.TryGetValue(ch, out var next))
                node.Children[ch] = next = new TrieNode();
            node = next;
            node.WordsBelow++;
        }
        node.IsWord = true;
    }

    public bool Contains(string word) => Find(word)?.IsWord == true;

    public int CountWithPrefix(string prefix) => Find(prefix)?.WordsBelow ?? 0;

    private TrieNode? Find(string prefix)
    {
        var node = _root;
        foreach (var ch in prefix)
            if (!node.Children.TryGetValue(ch, out node))
                return null;
        return node;
    }
}
```

Для слов car, card, care, cat, dog префикс «car» дают три слова, «ca» — четыре. Применение — автодополнение, поиск по префиксу, словари. Цена — память: узел со своим словарём на каждый символ.

## Графы

Граф — вершины и рёбра без ограничений дерева: циклы допустимы, связность не обязательна. Рёбра бывают **ориентированными** (подписка, зависимость) и неориентированными (дружба, дорога), **взвешенными** (расстояние, цена) и нет. Ориентированный граф без циклов (**DAG**) — отдельный важный случай: зависимости сборки, порядок миграций, задачи в конвейере. Для него определена топологическая сортировка — порядок, в котором каждая вершина идёт после всех, от кого зависит.

Сложность алгоритмов на графах выражают через две переменные: `V` — число вершин и `E` — число рёбер. Обход графа — O(V + E).

## Как хранить граф

Два основных представления:

**Матрица смежности** — двумерный массив `V × V`, где ячейка `[a, b]` говорит, есть ли ребро. Проверка ребра — O(1), но память O(V²) независимо от числа рёбер, и перебор соседей вершины — O(V).

**Списки смежности** — для каждой вершины список её соседей. Память O(V + E), перебор соседей — O(степени вершины), проверка конкретного ребра — O(степени).

```csharp
static List<int>[] BuildGraph(int vertexCount, (int From, int To)[] edges)
{
    var graph = new List<int>[vertexCount];
    for (int i = 0; i < vertexCount; i++)
        graph[i] = [];
    foreach (var (from, to) in edges)
    {
        graph[from].Add(to);
        graph[to].Add(from);
    }
    return graph;
}
```

Разница в памяти на типичном разреженном графе — 10 000 вершин и 50 000 неориентированных рёбер:

```
bool[10000, 10000]                    100,0 МБ
List<int>[] — списки смежности          1,2 МБ
Dictionary<int, List<int>>              1,6 МБ
```

В восемьдесят раз меньше. Реальные графы почти всегда разреженные, поэтому списки смежности — выбор по умолчанию. Матрица оправдана для плотных графов и маленьких `V`, где важна проверка ребра за O(1).

Если вершины — не числа от 0 до `V − 1`, а строки или идентификаторы, берут `Dictionary<TKey, List<TKey>>`. На собеседовании граф часто приходит списком рёбер, и первый шаг решения — построить из него списки смежности.

## Что стоит ответить на собеседовании

Дерево — связный граф без циклов, и операции над ним стоят O(высоты). В двоичном дереве поиска левые ключи меньше, правые больше, поэтому поиск — O(log n) на сбалансированном дереве, но на отсортированном входе оно вырождается в список: на 10 000 ключей высота 10 000 вместо 34. Отсюда красно-чёрные и AVL-деревья с гарантированной высотой O(log n) — на них построены `SortedSet` и `SortedDictionary`; в отличие от хеш-таблицы они дают порядок и диапазоны.

Сильный ответ добавит кучу — дерево в массиве с минимумом в корне и O(log n) на вставку и извлечение, это `PriorityQueue` в .NET, — и trie для поиска по префиксу. Про графы объяснит выбор представления: матрица смежности даёт проверку ребра за O(1), но O(V²) памяти — 100 МБ на 10 000 вершин, — а списки смежности занимают O(V + E), около 1,2 МБ на том же графе, поэтому для разреженных графов выбирают их.
