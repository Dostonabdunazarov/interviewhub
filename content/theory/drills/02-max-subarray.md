Задача о максимальной сумме подмассива (Maximum Subarray) проверяет, умеет ли кандидат увидеть динамическое программирование там, где оно занимает две переменные. Ответ «алгоритм Кадане» знают многие, но на собеседовании его просят объяснить: почему отрицательную сумму можно выбросить, что вернуть на массиве из одних отрицательных чисел и как достать границы отрезка.

## Условие и уточняющие вопросы

Дан массив целых чисел. Найти непрерывный подмассив с наибольшей суммой и вернуть эту сумму.

Вопросы, которые стоит задать:

- **Разрешён ли пустой подмассив?** От этого зависит ответ на `[-3, -1, -2]`: −1 или 0.
- **Может ли массив быть пустым?** Если да — что возвращать: исключение или договорное значение.
- **Нужна только сумма или ещё границы?**
- **Какой диапазон значений и длина?** Сумма миллиона `int` в `int` не помещается.
- **Подмассив непрерывный?** Если нет — ответ тривиален: сумма всех положительных.

Дальше считаем: подмассив непустой, массив непустой, нужна сумма.

## Перебор: O(n²)

Перебрать все пары границ `(i, j)` и посчитать сумму — O(n³), если пересчитывать каждую сумму заново. Очевидное улучшение — накапливать сумму при движении правой границы:

```csharp
static long BruteForce(int[] a)
{
    if (a.Length == 0) throw new ArgumentException("Массив пуст", nameof(a));
    long best = long.MinValue;
    for (int i = 0; i < a.Length; i++)
    {
        long sum = 0;
        for (int j = i; j < a.Length; j++)
        {
            sum += a[j];
            best = Math.Max(best, sum);
        }
    }
    return best;
}
```

O(n²) времени, O(1) памяти. Этот вариант полезен не только как стартовая точка: он служит эталоном, с которым потом сверяются быстрые решения.

Почему не скользящее окно? Окну нужна монотонность: расширение должно только увеличивать сумму, сжатие — только уменьшать. С отрицательными числами это не так, и левый край окна невозможно сдвигать по простому правилу (подробно — в разделе «Когда окно не работает» статьи `Скользящее окно`).

## Шаг к линейному решению: префиксные суммы

Сумма отрезка `(i, j]` равна `prefix[j] - prefix[i]`. Чтобы для фиксированного `j` она была максимальной, `prefix[i]` должен быть минимальным среди уже пройденных. Значит, достаточно одного прохода с двумя переменными:

```csharp
static long PrefixMin(ReadOnlySpan<int> a)
{
    if (a.IsEmpty) throw new ArgumentException("Массив пуст");
    long prefix = 0, minPrefix = 0, best = long.MinValue;
    foreach (int x in a)
    {
        prefix += x;
        best = Math.Max(best, prefix - minPrefix);
        minPrefix = Math.Min(minPrefix, prefix);
    }
    return best;
}
```

Начальное `minPrefix = 0` — это пустой префикс, то есть отрезок, начинающийся с нулевого индекса. Обновление минимума идёт **после** подсчёта ответа, иначе получится пустой отрезок с суммой 0. Это уже O(n) и O(1), и на собеседовании такой путь рассуждения засчитывают так же, как Кадане.

## Алгоритм Кадане

Та же идея в форме динамического программирования. Пусть `current` — лучшая сумма подмассива, который **заканчивается** в позиции `i`. Такой подмассив либо состоит из одного `a[i]`, либо продолжает лучший подмассив, заканчивающийся в `i - 1`:

```
current(i) = max(a[i], current(i - 1) + a[i])
```

Ответ — максимум `current` по всем позициям. Состояние ДП занимает одну переменную, поэтому таблица не нужна (как переходят от таблицы к переменным, разобрано в `Динамическое программирование`).

Интуиция: если накопленная сумма стала отрицательной, она только ухудшит любой следующий подмассив, и выгоднее начать заново с текущего элемента.

## Финальное решение

```csharp
static long MaxSubArray(ReadOnlySpan<int> a)
{
    if (a.IsEmpty) throw new ArgumentException("Массив пуст", nameof(a));
    long current = a[0], best = a[0];
    for (int i = 1; i < a.Length; i++)
    {
        current = Math.Max(a[i], current + a[i]);
        best = Math.Max(best, current);
    }
    return best;
}
```

`ReadOnlySpan<int>` позволяет передать и массив, и его часть без копирования (см. `Span<T> и Memory<T>`). Суммы в `long`: два `int.MaxValue` подряд дают 4 294 967 294, что в `int` превратилось бы в −2.

Прогон на классическом примере `[-2, 1, -3, 4, -1, 2, 1, -5, 4]`:

| i | a[i] | current | best |
| --- | --- | --- | --- |
| 0 | −2 | −2 | −2 |
| 1 | 1 | 1 | 1 |
| 2 | −3 | −2 | 1 |
| 3 | 4 | 4 | 4 |
| 4 | −1 | 3 | 4 |
| 5 | 2 | 5 | 5 |
| 6 | 1 | 6 | 6 |
| 7 | −5 | 1 | 6 |
| 8 | 4 | 5 | 6 |

Ответ 6 — подмассив `[4, -1, 2, 1]`.

## Сложность

Время O(n): один проход, на каждом шаге две операции сравнения. Память O(1). Для сравнения: перебор O(n²), «разделяй и властвуй» — O(n log n) и O(log n) на стек рекурсии; его иногда просят как упражнение, но практического смысла в нём нет.

## Границы подмассива

Если нужны индексы, запоминаем, где начался текущий отрезок, и фиксируем лучший:

```csharp
static (long Sum, int Start, int End) MaxSubArrayRange(ReadOnlySpan<int> a)
{
    if (a.IsEmpty) throw new ArgumentException("Массив пуст", nameof(a));
    long current = a[0], best = a[0];
    int start = 0, bestStart = 0, bestEnd = 0;
    for (int i = 1; i < a.Length; i++)
    {
        if (current < 0)
        {
            current = a[i];
            start = i;
        }
        else
        {
            current += a[i];
        }
        if (current > best)
        {
            best = current;
            bestStart = start;
            bestEnd = i;
        }
    }
    return (best, bestStart, bestEnd);
}
```

Условие `current < 0` эквивалентно `current + a[i] < a[i]`, только читается проще. На примере выше результат `(6, 3, 6)`. Строгое `>` при обновлении лучшего означает, что из нескольких отрезков с равной суммой вернётся тот, что закончился раньше, — если это важно, стоит сказать об этом.

## Крайние случаи и тесты

- **Все числа отрицательные.** `[-3, -1, -2]` → −1, отрезок из одного элемента. Самая частая ошибка — инициализировать `best = 0`: тогда вернётся 0, то есть пустой подмассив, который по условию запрещён.
- **Пустой подмассив разрешён.** Тогда как раз нужен ноль снизу: `current = Math.Max(0, current + x)`, `best` стартует с нуля, и `[-3, -1, -2]` даёт 0.
- **Один элемент** → он сам.
- **Пустой массив** → `ArgumentException`, как договорились.
- **Переполнение** → `[int.MaxValue, int.MaxValue]` даёт 4 294 967 294 благодаря `long`.

Все три версии — Кадане, префиксные суммы и вариант с границами — сверены с перебором на трёх тысячах случайных массивов длиной до 25 с числами от −10 до 9: расхождений нет, а сумма элементов на возвращённом отрезке всегда равна ответу.

## Вариации, которые спрашивают следом

**Максимальное произведение подмассива.** Минус на минус даёт плюс, поэтому хранят и максимум, и минимум произведения, заканчивающегося в позиции; на отрицательном элементе они меняются местами:

```csharp
static long MaxProduct(ReadOnlySpan<int> a)
{
    if (a.IsEmpty) throw new ArgumentException("Массив пуст", nameof(a));
    long max = a[0], min = a[0], best = a[0];
    for (int i = 1; i < a.Length; i++)
    {
        long x = a[i];
        if (x < 0) (max, min) = (min, max);
        max = Math.Max(x, max * x);
        min = Math.Min(x, min * x);
        best = Math.Max(best, max);
    }
    return best;
}
```

`[2, 3, -2, 4]` → 6, `[-2, 3, -4]` → 24, `[-2, 0, -1]` → 0. Для длинных массивов `long` тоже переполнится — это стоит оговорить.

**Кольцевой массив.** Отрезок может «обернуться» через конец. Ответ — максимум из обычного Кадане и `total - minSubarray`: выбросить из кольца отрезок с минимальной суммой. Исключение — все числа отрицательные: тогда `total - minSubarray` даёт пустой отрезок, и надо вернуть обычный максимум. `[5, -3, 5]` → 10.

**Лучшее время купить и продать акцию.** Тот же Кадане по разностям соседних дней, либо проще — держать минимальную цену до текущего дня. `[7, 1, 5, 3, 6, 4]` → 5.

**Подмассив с суммой ровно k.** Это уже не максимум, а подсчёт, и решается префиксными суммами со словарём — код есть в статье `Скользящее окно`.

**Двумерный вариант** — максимальная сумма подматрицы: фиксируем пару строк, сжимаем столбцы в одномерный массив сумм и запускаем Кадане. O(n²·m).

## Что стоит ответить на собеседовании

Сначала уточнить, разрешён ли пустой подмассив и что делать с пустым массивом. Затем назвать перебор с накопительной суммой за O(n²) и перейти к Кадане: `current` — лучшая сумма подмассива, заканчивающегося в текущей позиции, она равна `max(a[i], current + a[i])`, а ответ — максимум по всем позициям. O(n) времени и O(1) памяти. Интуиция — отрицательный накопленный префикс только мешает, его выгодно отбросить.

Сильный ответ показывает, что это ДП с состоянием в одну переменную, объясняет, почему `best = 0` ломает массив из отрицательных чисел, считает суммы в `long`, умеет вернуть границы отрезка и знает вариации: произведение с парой max/min, кольцевой массив через `total - minSubarray`, акции через минимум цены.
