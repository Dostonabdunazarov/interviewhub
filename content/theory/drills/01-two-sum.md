Two Sum — самая частая разминочная задача на алгоритмической секции. Решение в одну строку мысли знает почти каждый, поэтому оценивают не сам факт решения, а ход: какие вопросы задали, с чего начали, как обосновали переход к быстрому варианту и какие крайние случаи проверили. Ниже — тот путь, который ждут от кандидата.

## Условие и уточняющие вопросы

Дан массив целых чисел `nums` и число `target`. Найти индексы двух разных элементов, сумма которых равна `target`.

Прежде чем писать код, стоит задать вопросы — каждый из них меняет решение:

- **Индексы или значения?** Если нужны только значения, массив можно сортировать; если индексы — сортировка их теряет.
- **Отсортирован ли массив?** На отсортированном есть решение за O(1) памяти.
- **Одна пара или все?** Если все — нужны ли уникальные пары значений или все пары индексов.
- **Могут ли быть дубликаты?** `[3, 3]` при `target = 6` — валидный ответ.
- **Что вернуть, если пары нет?** `null`, пустой результат или исключение.
- **Какой диапазон чисел?** Сумма двух `int` может не поместиться в `int`.

Дальше считаем: массив произвольный, нужны индексы любой одной пары, при отсутствии — `null`.

## Перебор: O(n²)

Начать с перебора — нормально, если сразу назвать его сложность и сказать, что это отправная точка:

```csharp
static (int, int)? BruteForce(int[] nums, int target)
{
    for (int i = 0; i < nums.Length; i++)
        for (int j = i + 1; j < nums.Length; j++)
            if ((long)nums[i] + nums[j] == target)
                return (i, j);
    return null;
}
```

Пар n·(n−1)/2, поэтому время O(n²), память O(1). Внутренний цикл начинается с `i + 1`: так элемент не складывается сам с собой и каждая пара проверяется один раз. Замер на .NET 10: на 10 000 элементов без подходящей пары перебор занимает 49,5 мс, а решение со словарём из следующего пункта — 0,22 мс. Разница в двести с лишним раз, и она растёт квадратично (почему — в `O(1) … O(n²) на примерах`).

## Наблюдение, которое убирает внутренний цикл

Внутренний цикл ищет конкретное значение — `target - nums[i]`. Поиск значения в массиве линеен, а в хеш-таблице — константа в среднем (см. `Хеш-таблица`). Значит, достаточно помнить уже пройденные элементы в словаре «значение → индекс» и для каждого нового спрашивать, видели ли мы его дополнение.

Это шаблон «значение → позиция» из статьи `Dictionary vs HashSet на практике`: один проход, на каждом шаге — один поиск и одна вставка.

## Решение со словарём: O(n)

```csharp
static (int, int)? TwoSum(int[] nums, int target)
{
    var seen = new Dictionary<int, int>(nums.Length);
    for (int i = 0; i < nums.Length; i++)
    {
        long need = (long)target - nums[i];
        if (need is >= int.MinValue and <= int.MaxValue
            && seen.TryGetValue((int)need, out int j))
            return (j, i);
        seen.TryAdd(nums[i], i);
    }
    return null;
}
```

Три детали, которые стоит проговорить вслух.

**Сначала проверка, потом вставка.** Если сначала добавить `nums[i]`, а потом искать дополнение, то при `target = 6` и `nums[i] = 3` элемент найдёт сам себя. При обратном порядке `[3, 2, 4]` корректно даёт `(1, 2)`, а `[3, 3]` — `(0, 1)`: второй элемент находит первый.

**Дополнение считается в `long`.** В C# арифметика по умолчанию `unchecked`, и `target - nums[i]` молча переполняется. На `[int.MinValue, int.MinValue + 4]` с `target = 4` наивная версия с `int need` проверена и возвращает `(0, 1)`, хотя сумма этих чисел равна −2³² + 4, а не 4. Дополнение, вышедшее за диапазон `int`, в массиве встретиться не может — его просто пропускаем.

**`TryAdd` вместо индексатора.** При дубликатах в словаре остаётся первый индекс значения. Для «любой пары» это неважно, но если интервьюер попросит «пару с наименьшим правым индексом» или «самую раннюю», поведение уже определено, а не случайно.

`capacity` задан заранее, чтобы словарь не перестраивался по мере роста (подробнее — в `Как устроен Dictionary`).

## Сложность

Время O(n): один проход, на каждом шаге поиск и вставка в словарь за O(1) в среднем. Память O(n) на словарь в худшем случае, когда пара не нашлась или нашлась в самом конце.

Оговорка «в среднем» не формальность: при плохом хеше или специально подобранных ключах словарь деградирует. Для `int` хеш — само число, и атака коллизиями на учебной задаче не грозит, но упомянуть, что O(1) — амортизированная оценка, полезно.

## Отсортированный массив: два указателя

Если массив отсортирован, словарь не нужен. Указатели ставятся на концы и двигаются навстречу: сумма мала — сдвигаем левый, велика — правый.

```csharp
static (int, int)? TwoSumSorted(int[] a, int target)
{
    int left = 0, right = a.Length - 1;
    while (left < right)
    {
        long sum = (long)a[left] + a[right];
        if (sum == target) return (left, right);
        if (sum < target) left++;
        else right--;
    }
    return null;
}
```

Время O(n), память O(1). Почему ни одна пара не теряется, подробно разобрано в статье `Два указателя`: сдвигая указатель, мы отбрасываем все пары с покинутым элементом разом, и это обосновано монотонностью.

Сортировать произвольный массив ради этого варианта имеет смысл, только когда нужны значения, а не индексы: сортировка стоит O(n log n), а исходные позиции придётся хранить отдельно. Промежуточный вариант — бинарный поиск дополнения для каждого элемента, O(n log n) и O(1) памяти; он хуже двух указателей и упоминается скорее для полноты (см. `Бинарный поиск`).

| Подход | Время | Память |
| --- | --- | --- |
| перебор пар | O(n²) | O(1) |
| словарь, один проход | O(n) | O(n) |
| массив отсортирован, два указателя | O(n) | O(1) |
| сортировка + два указателя | O(n log n) | O(n) с индексами, O(1) без |

## Крайние случаи и тесты

Набор, который стоит прогнать хотя бы устно — все варианты ниже проверены на коде из статьи:

| Вход | target | Ожидание | Что проверяет |
| --- | --- | --- | --- |
| `[2, 7, 11, 15]` | 9 | `(0, 1)` | базовый случай |
| `[3, 2, 4]` | 6 | `(1, 2)` | элемент не складывается сам с собой |
| `[3, 3]` | 6 | `(0, 1)` | дубликаты |
| `[]`, `[5]` | 10 | `null` | пустой и одиночный массив |
| `[1, 2, 3]` | 100 | `null` | пары нет |
| `[-3, 4, 3, 90]` | 0 | `(0, 2)` | отрицательные числа |
| `[int.MinValue, int.MinValue + 4]` | 4 | `null` | переполнение дополнения |

Помимо таблицы, быстрые решения сверялись с перебором на двух тысячах случайных массивов с отрицательными числами и повторами: совпало наличие пары во всех случаях, и каждая найденная пара давала нужную сумму.

## Вариации, которые спрашивают следом

**Все уникальные пары значений.** Сортировка и два указателя, но после найденной пары оба указателя проматываются мимо одинаковых значений. Для `[1, 1, 2, 3, 4, 5, 5, 3]` и `target = 6` получается `(1, 5)`, `(2, 4)`, `(3, 3)` — без повторов.

**Количество пар индексов.** Словарь «значение → сколько раз встречалось»: на каждом шаге к ответу прибавляется счётчик дополнения, потом увеличивается счётчик текущего значения. O(n).

**3Sum и 4Sum.** Фиксируем один элемент и решаем Two Sum двумя указателями на остатке отсортированного массива — O(n²); для 4Sum ещё один уровень, O(n³). Код 3Sum с пропуском дубликатов есть в статье `Два указателя`.

**Ближайшая сумма.** Те же два указателя, только вместо проверки на равенство обновляется лучший ответ по `|sum - target|`.

**Two Sum в бинарном дереве поиска.** Обход in-order даёт отсортированную последовательность, дальше — два указателя; либо обход с `HashSet` увиденных значений, как в основном решении.

**Поток данных.** Если числа приходят по одному и запросов «есть ли пара с суммой X» много, выбор зависит от соотношения операций: словарь частот делает `add` за O(1), а `find` за O(n) по уникальным значениям; хранение всех попарных сумм делает наоборот. Интервьюер ждёт, что вы спросите, какая операция чаще.

## Что стоит ответить на собеседовании

Сначала задать вопросы: индексы или значения, отсортирован ли массив, одна пара или все, что делать без ответа и каков диапазон чисел. Затем назвать перебор за O(n²) и сразу объяснить, что внутренний цикл ищет конкретное значение `target - x`, а поиск значения можно сделать за O(1) словарём «значение → индекс». Итог — один проход, O(n) времени и O(n) памяти.

Сильный ответ проговаривает порядок «сначала проверить, потом добавить» — он защищает от сложения элемента с самим собой и правильно обрабатывает `[3, 3]`, — считает дополнение в `long` из-за `unchecked`-арифметики и знает альтернативу для отсортированного массива: два указателя за O(n) и O(1) памяти. Вариации — уникальные пары, подсчёт пар, 3Sum за O(n²) — решаются теми же двумя идеями.
