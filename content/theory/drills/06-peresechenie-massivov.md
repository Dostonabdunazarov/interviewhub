Пересечение массивов — задача, в которой главная ловушка в условии, а не в алгоритме. «Общие элементы» можно понять двумя способами, и решение под каждый своё. Дальше интервьюер варьирует данные: отсортированы ли массивы, сильно ли различаются по размеру, помещаются ли в память. Каждая такая вариация меняет лучший ответ, и это хорошая проверка, понимает ли кандидат, откуда берётся сложность.

## Условие и уточняющие вопросы

Даны два массива целых чисел. Вернуть их пересечение.

Главный вопрос — **что такое пересечение**:

- **уникальные общие значения**: `[1, 2, 2, 1] ∩ [2, 2] = [2]`;
- **с учётом кратности**: элемент входит столько раз, сколько он встречается в обоих, то есть минимум из двух количеств: `[1, 2, 2, 1] ∩ [2, 2] = [2, 2]`.

Остальные вопросы:

- **Важен ли порядок результата?**
- **Отсортированы ли массивы?**
- **Насколько различаются размеры?** Десять элементов против миллиона — отдельный случай.
- **Помещаются ли оба массива в память?**
- **Можно ли менять входные данные** — например, сортировать на месте?

Начнём с уникальных значений и произвольного порядка.

## Перебор: O(n·m)

Для каждого элемента первого массива искать его во втором линейным поиском и не добавлять повторно:

```csharp
static List<int> BruteForce(int[] a, int[] b)
{
    var result = new List<int>();
    foreach (int x in a)
        if (Array.IndexOf(b, x) >= 0 && !result.Contains(x))
            result.Add(x);
    return result;
}
```

O(n·m) на поиски во втором массиве плюс ещё до O(n²) на проверку `result.Contains`. Узкое место то же, что в `Two sum`: внутри цикла идёт поиск значения, а поиск значения в хеш-таблице стоит O(1) в среднем.

## Уникальные значения: HashSet

Строим множество из одного массива, проходим по второму и забираем то, что есть в множестве:

```csharp
static List<int> Intersection(int[] a, int[] b)
{
    if (a.Length > b.Length) (a, b) = (b, a);
    var set = new HashSet<int>(a);
    var result = new List<int>();
    foreach (int x in b)
        if (set.Remove(x))
            result.Add(x);
    return result;
}
```

Детали:

- **Множество строится из меньшего массива** — память O(min(n, m)). Обмен ссылок кортежем не трогает сами массивы.
- **`Remove` вместо `Contains`.** `HashSet.Remove` возвращает `true`, только если элемент был. Найденный элемент удаляется, поэтому повторное вхождение во втором массиве уже не попадёт в результат — второе множество для уникальности не нужно. Это та же идея, что «`Add` возвращает `bool`» из статьи `HashSet<T>`.
- Порядок результата — порядок первого появления в большем массиве.

Время O(n + m) в среднем: построение множества и один проход с поиском за O(1). Память O(min(n, m)).

## С учётом кратности: словарь частот

Множество теряет количество, поэтому вместо него — словарь «значение → сколько раз осталось». Каждое совпадение уменьшает счётчик:

```csharp
static List<int> IntersectionWithCounts(int[] a, int[] b)
{
    if (a.Length > b.Length) (a, b) = (b, a);
    var count = new Dictionary<int, int>(a.Length);
    foreach (int x in a)
        count[x] = count.GetValueOrDefault(x) + 1;

    var result = new List<int>();
    foreach (int x in b)
    {
        if (count.TryGetValue(x, out int c) && c > 0)
        {
            result.Add(x);
            count[x] = c - 1;
        }
    }
    return result;
}
```

Это шаблон «подсчёт частот» из `Dictionary vs HashSet на практике`. `[4, 9, 5] ∩ [9, 4, 9, 8, 4]` даёт `[9, 4]`: каждое значение есть в меньшем массиве по разу, поэтому вторые `9` и `4` уже не проходят. Сложность та же: O(n + m) времени, O(min(n, m)) памяти.

## Отсортированные массивы: два указателя

Если оба массива отсортированы, хеш-таблица не нужна. Указатели движутся по каждому массиву: меньший элемент не может встретиться в другом массиве дальше, поэтому его указатель сдвигается; на равенстве — совпадение, сдвигаются оба.

```csharp
static List<int> IntersectSorted(ReadOnlySpan<int> a, ReadOnlySpan<int> b)
{
    var result = new List<int>();
    int i = 0, j = 0;
    while (i < a.Length && j < b.Length)
    {
        if (a[i] < b[j]) i++;
        else if (a[i] > b[j]) j++;
        else
        {
            result.Add(a[i]);
            i++;
            j++;
        }
    }
    return result;
}
```

Эта версия сразу считает кратность: `[1, 2, 2, 3] ∩ [2, 2, 2, 3, 4] = [2, 2, 3]`. Для уникальных значений достаточно не добавлять элемент, равный последнему добавленному, — результат и так отсортирован. O(n + m) времени и O(1) памяти сверх результата; обоснование, почему такой сдвиг ничего не теряет, — в статье `Два указателя`.

Если массивы не отсортированы, но их можно менять, сортировка обоих даёт O(n log n + m log m) и O(1) дополнительной памяти, без хеш-таблицы. Это ответ на вопрос «а если память ограничена».

## Сильно разные размеры: бинарный поиск

Десять элементов против отсортированного миллиона. Два указателя пройдут весь миллион, множество из десяти элементов — тоже. А бинарный поиск каждого маленького элемента в большом массиве — это O(k log n), где k — размер маленького: десять поисков по двадцать сравнений.

```csharp
static List<int> IntersectSmallWithHuge(int[] small, int[] hugeSorted)
{
    var result = new List<int>();
    foreach (int x in small)
        if (Array.BinarySearch(hugeSorted, x) >= 0)
            result.Add(x);
    return result;
}
```

Здесь `small` предполагается без повторов; иначе его сначала пропускают через `HashSet`. Подробнее о самом поиске — в статье `Бинарный поиск`.

| Подход | Время | Память |
| --- | --- | --- |
| вложенные циклы | O(n·m) | O(1) |
| `HashSet` из меньшего | O(n + m) | O(min(n, m)) |
| сортировка обоих + два указателя | O(n log n + m log m) | O(1)* |
| оба уже отсортированы | O(n + m) | O(1) |
| маленький против большого отсортированного | O(k log n) | O(1) |

\* если входные массивы можно менять; иначе плюс копии.

## Встроенные средства .NET

- `a.Intersect(b)` — LINQ, уникальные значения: строит множество из `b` и отдаёт элементы `a` в их порядке, выкидывая найденные из множества. `[1, 2, 2, 3].Intersect([2, 3, 3])` → `[2, 3]`.
- `set.IntersectWith(other)` — меняет само множество на месте.
- `IntersectBy(keys, keySelector)` (.NET 6+) — пересечение объектов по ключу.

На собеседовании `Intersect` уместно назвать, но решение всё равно просят написать руками: проверяют понимание, а не знание API. Кратность `Intersect` не учитывает — это частая ошибка, если её применить к варианту «с учётом кратности».

## Крайние случаи и тесты

- Один или оба пустые → пустой результат.
- Нет общих элементов: `[1, 2] ∩ [3, 4]` → пусто.
- Повторы с обеих сторон — проверяют, какую семантику выбрали: `[1, 2, 2, 1] ∩ [2, 2]` даёт `[2]` или `[2, 2]`.
- Один массив сильно больше другого — проверяет, что множество строится из меньшего.
- Отрицательные числа и `int.MinValue` — для хеш-решений ничего не меняют.

Все реализации сверены с перебором на трёх тысячах пар случайных массивов длиной до 19 со значениями от 0 до 11 — так повторы встречаются почти в каждом тесте. Вариант с кратностью сверялся с минимумом количеств каждого значения.

## Вариации, которые спрашивают следом

**Пересечение k массивов.** Множество из первого, затем `IntersectWith` с каждым следующим; если множество опустело — дальше можно не идти. Для кратности — словарь минимальных счётчиков. Выгодно начинать с самого маленького массива.

**Второй массив не помещается в память.** Меньший держим в `HashSet` или словаре частот, больший читаем потоком с диска или из сети — память O(min). Если в память не помещается ни один, сортируем оба внешней сортировкой и пересекаем двумя указателями на потоках — та же техника, что слияние в статье `Слияние отсортированных массивов`.

**Данные распределены по узлам.** Шардируем оба набора одной хеш-функцией по значению: общие элементы попадут на один узел, и каждый узел пересекает свою часть независимо. Так работает hash join в базах данных — и это хороший мост от алгоритмической задачи к разговору про `JOIN`.

**Пересечение по полю объектов.** `IntersectBy` или своё `IEqualityComparer<T>` для `HashSet<T>`; требования к ключу те же, что у ключа словаря (см. `Equals, GetHashCode и ==: как устроено равенство`).

**Объединение и разность.** Те же инструменты: `UnionWith` и `ExceptWith` для множеств или слияние двумя указателями для отсортированных данных.

## Что стоит ответить на собеседовании

Первым делом уточнить, уникальные значения нужны или с учётом кратности. Для уникальных — `HashSet` из меньшего массива и проход по большему, O(n + m) времени и O(min(n, m)) памяти; `Remove` вместо `Contains` заодно убирает повторы из результата. Для кратности — словарь частот с уменьшением счётчика.

Сильный ответ разбирает, как меняется решение от данных: на отсортированных массивах — два указателя с O(1) памяти, при сильно разных размерах — бинарный поиск за O(k log n), при нехватке памяти — сортировка на месте или потоковое чтение большего массива, при распределённых данных — шардирование по значению, как в hash join. И помнит, что LINQ `Intersect` возвращает уникальные значения и для варианта с кратностью не подходит.
