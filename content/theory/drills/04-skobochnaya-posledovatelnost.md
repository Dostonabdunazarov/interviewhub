Проверка скобок — короткая задача, на которой проверяют, узнаёт ли кандидат стек в постановке, где слово «стек» не звучит. Код занимает десять строк, поэтому больше внимания уходит на обоснование: почему не хватает счётчиков, какие три вида ошибок бывают и что делать с посторонними символами.

## Условие и уточняющие вопросы

Дана строка из символов `()[]{}`. Определить, корректна ли она: каждая открывающая скобка закрыта скобкой того же вида, и вложенность не нарушена.

Вопросы:

- **Какие виды скобок?** Если только круглые — решение проще (см. ниже).
- **Есть ли в строке другие символы?** Игнорировать их или считать ошибкой.
- **Пустая строка корректна?** Обычно да.
- **Нужен только ответ да/нет или позиция ошибки?**
- **Какая максимальная длина?** Влияет на выбор между `Stack<T>` и буфером на стеке потока.

Считаем: три вида скобок, посторонний символ — ошибка входных данных, пустая строка корректна.

## Почему не работают счётчики

Первая мысль — посчитать открывающие и закрывающие каждого вида и сравнить. Это ловит `"(()"`, но пропускает две ошибки:

- `")("` — счётчики равны, но закрыли раньше, чем открыли;
- `"([)]"` — счётчики каждого вида равны, но вложенность нарушена: внутри `[` закрывается `(`.

Вторая ошибка и есть суть задачи. Закрывающая скобка должна соответствовать **последней** ещё не закрытой открывающей, а «последний пришёл — первый ушёл» — это стек (см. `Стек и очередь`).

## Перебор: удаление пар

Есть решение без стека, которое иногда предлагают первым: пока в строке есть `()`, `[]` или `{}`, удалять их; строка корректна, если в итоге стала пустой.

```csharp
static bool BruteForce(string s)
{
    string prev;
    do
    {
        prev = s;
        s = s.Replace("()", "").Replace("[]", "").Replace("{}", "");
    } while (s.Length != prev.Length);
    return s.Length == 0;
}
```

Оно верное, но на строке вида `"((((…))))"` каждый проход снимает одну пару, а каждый `Replace` создаёт новую строку длины O(n). Итог — O(n²) времени и O(n²) суммарных аллокаций. Зато это удобный эталон для тестов: на нём проверялись все версии ниже.

## Решение стеком

Открывающая скобка кладётся в стек. На закрывающей проверяем, что стек не пуст и на вершине лежит парная открывающая, и снимаем её. В конце строка корректна, только если стек пуст.

```csharp
static bool IsValid(string s)
{
    if (s.Length % 2 != 0) return false;
    var stack = new Stack<char>(s.Length / 2);
    foreach (char c in s)
    {
        switch (c)
        {
            case '(' or '[' or '{':
                stack.Push(c);
                break;
            case ')' or ']' or '}':
                char open = c switch { ')' => '(', ']' => '[', _ => '{' };
                if (!stack.TryPop(out char top) || top != open) return false;
                break;
            default:
                throw new ArgumentException($"Недопустимый символ '{c}'", nameof(s));
        }
    }
    return stack.Count == 0;
}
```

Детали:

- **Ранний выход по нечётной длине** корректен, только когда в строке нет ничего, кроме скобок. Если посторонние символы разрешены и игнорируются, эту строку надо убрать — `"(a)"` корректна, а длина у неё 3.
- **`TryPop`** совмещает проверку на пустоту и извлечение; `Pop` на пустом стеке бросил бы `InvalidOperationException`.
- **`capacity = s.Length / 2`**: в корректной строке глубина не больше половины длины. Если глубже — строка всё равно некорректна, и стек просто вырастет.

## Три вида ошибок

Каждая ветка алгоритма ловит свою ошибку:

| Строка | Ошибка | Что срабатывает |
| --- | --- | --- |
| `"(]"` | не та пара | на вершине не `[` |
| `"())"` | лишняя закрывающая | `TryPop` на пустом стеке |
| `"(()"` | незакрытая открывающая | стек не пуст в конце |
| `"([)]"` | нарушена вложенность | на `)` вершина — `[` |

На собеседовании полезно пройтись по этой таблице вслух: она показывает, что решение покрывает все случаи, а не только пример из условия.

## Сложность

Время O(n): каждый символ обрабатывается один раз, `Push` и `Pop` — O(1). Память O(n) в худшем случае — на строке из одних открывающих.

## Без аллокаций

`Stack<char>` — это объект и массив внутри. Замер на .NET 10: строка из 200 открывающих и 200 закрывающих скобок — 456 байт аллокаций на вызов. Для горячего пути, например валидации входящих выражений, стек можно держать в `Span<char>`:

```csharp
static bool IsValidSpan(ReadOnlySpan<char> s)
{
    if (s.Length % 2 != 0) return false;
    Span<char> stack = s.Length <= 512 ? stackalloc char[s.Length] : new char[s.Length];
    int top = 0;
    foreach (char c in s)
    {
        if (c is '(' or '[' or '{')
        {
            stack[top++] = c;
            continue;
        }
        char open = c switch { ')' => '(', ']' => '[', '}' => '{', _ => '\0' };
        if (open == '\0' || top == 0 || stack[--top] != open) return false;
    }
    return top == 0;
}
```

На той же строке — 0 байт. Порог 512 символов нужен, потому что `stackalloc` берёт память со стека потока, а он ограничен (см. `Span<T> и Memory<T>` и `Стек и куча`); длинная строка уходит в обычный массив. Здесь посторонний символ не бросает исключение, а делает строку некорректной — это другой контракт, и его стоит назвать. На собеседовании такую версию приводят как ответ на вопрос «а если это горячий путь», а не как основное решение.

## Один вид скобок — счётчик

Если скобки только круглые, стек хранил бы одинаковые символы, и важен лишь его размер. Достаточно счётчика глубины:

```csharp
static bool IsValidParens(string s)
{
    int depth = 0;
    foreach (char c in s)
    {
        if (c == '(') depth++;
        else if (c == ')' && --depth < 0) return false;
    }
    return depth == 0;
}
```

O(1) памяти. Проверка `--depth < 0` внутри цикла — это то, чего не хватало «простому подсчёту»: она ловит `")("`.

## Крайние случаи и тесты

- `""` → `true`;
- `"("`, `"]"` → `false`, одиночные скобки;
- `"{[()]}"` → `true`, глубокая вложенность разных видов;
- `")("` → `false`, порядок важен;
- `"((((("` → `false`, нечётная длина;
- `"(a)b"` → `ArgumentException` в основной версии и `false` в версии на `Span`;
- строка из 1000 открывающих и 1000 закрывающих → `true`, проверка ветки с массивом вместо `stackalloc`.

Кроме ручных случаев, обе версии сверены с удалением пар на двадцати тысячах случайных строк длиной до 11 — половина только из круглых скобок, половина из всех трёх видов.

## Вариации, которые спрашивают следом

**Позиция первой ошибки.** В стеке хранят индексы, а не символы. Ошибка — это либо закрывающая скобка без пары (её индекс), либо самая ранняя незакрытая открывающая (самый нижний элемент стека в конце). Для `"([)]"` ответ 2, для `"(()"` — 0.

**Минимум скобок, чтобы сделать строку корректной.** Для одного вида — два счётчика: незакрытые открывающие и закрывающие без пары. Ответ — их сумма. `"()))(("` → 4.

**Самая длинная корректная подстрока.** Стек индексов с «дном» −1: на `(` кладём индекс, на `)` снимаем; если стек опустел, кладём текущий индекс как новое дно, иначе длина — `i - stack.Peek()`. O(n). `")()())"` → 4. Проверено против перебора всех подстрок.

**Сгенерировать все корректные последовательности из n пар.** Бэктрекинг: ставим `(`, пока открытых меньше n, и `)`, пока закрытых меньше, чем открытых. Число вариантов — n-е число Каталана: 5 при n = 3, 14 при n = 4 (см. `Рекурсия и переполнение стека`).

**Вычисление выражения со скобками.** Два стека — операндов и операторов — или алгоритм сортировочной станции. Тот же принцип: закрывающая скобка «сворачивает» всё до парной открывающей.

## Что стоит ответить на собеседовании

Объяснить, почему счётчиков мало: `"([)]"` проходит подсчёт, но вложенность нарушена, а закрывающая скобка должна совпадать с последней незакрытой — это стек. Открывающие кладём, на закрывающей сверяем вершину и снимаем, в конце стек должен быть пуст. O(n) времени и O(n) памяти.

Сильный ответ называет три вида ошибок и какая ветка ловит каждую, использует `TryPop` вместо `Count` и `Pop`, уточняет, что делать с посторонними символами, и знает упрощение для одного вида скобок — счётчик глубины с проверкой на отрицательное значение, O(1) памяти. Для горячего пути — стек в `Span<char>` через `stackalloc` с порогом длины, без аллокаций.
