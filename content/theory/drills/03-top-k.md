«Найти k наибольших элементов» — задача, в которой правильный ответ зависит от вопросов, заданных до кода. Отсортировать и взять первые k умеют все; интервьюер ждёт, что кандидат заметит лишнюю работу, предложит кучу размера k и объяснит, когда она лучше сортировки, а когда — нет. Задача прямо переносится в бэкенд: топ запросов, самые медленные эндпоинты, самые активные пользователи.

## Условие и уточняющие вопросы

Дан массив (или поток) из n целых чисел и число k. Вернуть k наибольших.

Вопросы:

- **Насколько k меньше n?** Десять из миллиона и полмиллиона из миллиона — разные задачи.
- **Нужен ли порядок внутри результата?** Если нет, открывается quickselect.
- **Помещаются ли данные в память?** Или это поток, который читается один раз.
- **Можно ли менять входной массив?**
- **Что с дубликатами?** `[5, 5, 5, 1]` при k = 2 — это `[5, 5]` или `[5, 1]`?
- **Граничные k**: `k = 0`, `k > n`, отрицательное.

Дальше считаем: k ≪ n, результат нужен по убыванию, дубликаты считаются отдельными элементами, при `k > n` возвращаем всё.

## Решение в лоб: сортировка

Отсортировать копию по убыванию и взять первые k. O(n log n) времени, O(n) памяти на копию. Через LINQ это `OrderByDescending(x => x).Take(k)` — в современном .NET такая цепочка не сортирует весь массив полностью, а выбирает только нужную часть, но всё равно материализует источник целиком.

Лишняя работа здесь видна: мы упорядочиваем n элементов, хотя нужен порядок только среди k.

## Идея: держать только k кандидатов

Пройдём по данным и будем хранить k лучших на текущий момент. Каждый новый элемент сравнивается с **худшим** из кандидатов: если новый больше — худший вылетает. Чтобы худший доставался быстро, кандидатов держат в min-куче: минимум на вершине, вставка и удаление за O(log k). Как устроена куча, разобрано в `Деревья и графы`, а в .NET она уже есть — `PriorityQueue<TElement, TPriority>`.

Две детали этого класса, которые стоит знать:

- это **min-куча**: `Dequeue` возвращает элемент с наименьшим приоритетом; внутри — 4-арное дерево на массиве;
- порядок элементов с одинаковым приоритетом **не гарантирован**, а перечисление `UnorderedItems` идёт в порядке массива кучи, а не по приоритету.

## Финальное решение

```csharp
static int[] TopK(IEnumerable<int> source, int k)
{
    ArgumentOutOfRangeException.ThrowIfNegative(k);
    if (k == 0) return [];
    var heap = new PriorityQueue<int, int>(k);
    foreach (int x in source)
    {
        if (heap.Count < k) heap.Enqueue(x, x);
        else if (x > heap.Peek()) heap.DequeueEnqueue(x, x);
    }
    var result = new int[heap.Count];
    for (int i = result.Length - 1; i >= 0; i--)
        result[i] = heap.Dequeue();
    return result;
}
```

Пока куча не заполнена, элементы просто добавляются. Дальше новый элемент попадает в кучу, только если он больше текущего минимума: `DequeueEnqueue` (.NET 8+) снимает вершину и вставляет новый элемент за одно просеивание, а не за два. Элементы, которые не больше минимума, отсекаются за O(1) — на случайных данных это подавляющее большинство.

В конце куча отдаёт элементы по возрастанию, поэтому массив заполняется с конца — результат получается по убыванию. Вход — `IEnumerable<int>`: метод не требует, чтобы данные лежали в памяти, и работает на потоке.

Для k **наименьших** нужна max-куча — тот же класс с обратным компаратором приоритета: `new PriorityQueue<int, int>(k, Comparer<int>.Create((a, b) => b.CompareTo(a)))`, а условие вытеснения меняется на `x < heap.Peek()`.

## Сложность

Время O(n log k): n элементов, каждая операция с кучей размера k стоит O(log k). Память O(k). При k ≪ n это почти линейно, и выигрыш виден на замере (.NET 10, миллион случайных `int`, k = 10, медиана семи прогонов):

| Подход | Время |
| --- | --- |
| копия + `Array.Sort` | 70,3 мс |
| `OrderByDescending().Take(10)` | 32,8 мс |
| quickselect (k-й наибольший) | 6,1 мс |
| min-куча размера k | 2,9 мс |

Куча быстрее полной сортировки в 24 раза. Когда k приближается к n, преимущество исчезает: O(n log k) превращается в O(n log n), а константа у кучи выше, чем у `Array.Sort`. Ориентир для ответа — «куча, когда k намного меньше n или данные идут потоком».

## Quickselect: O(n) в среднем

Если порядок внутри результата не нужен и массив можно менять, есть решение быстрее асимптотически. Partition из quicksort ставит опорный элемент на его итоговое место; дальше рекурсия идёт только в ту половину, где лежит нужная позиция. В среднем n + n/2 + n/4 + … = O(n), в худшем — O(n²), поэтому опорный элемент выбирают случайно.

```csharp
static int KthLargest(int[] nums, int k)
{
    ArgumentOutOfRangeException.ThrowIfLessThan(k, 1);
    ArgumentOutOfRangeException.ThrowIfGreaterThan(k, nums.Length);
    Span<int> a = nums.ToArray();
    int target = a.Length - k;
    int lo = 0, hi = a.Length - 1;
    while (true)
    {
        int p = Partition(a, lo, hi, Random.Shared.Next(lo, hi + 1));
        if (p == target) return a[p];
        if (p < target) lo = p + 1;
        else hi = p - 1;
    }
}

static int Partition(Span<int> a, int lo, int hi, int pivotIndex)
{
    int pivot = a[pivotIndex];
    (a[pivotIndex], a[hi]) = (a[hi], a[pivotIndex]);
    int store = lo;
    for (int i = lo; i < hi; i++)
    {
        if (a[i] < pivot)
        {
            (a[i], a[store]) = (a[store], a[i]);
            store++;
        }
    }
    (a[store], a[hi]) = (a[hi], a[store]);
    return store;
}
```

После возврата всё правее позиции `target` в копии — это k − 1 элементов не меньше найденного, то есть top K без порядка. На замере выше quickselect проиграл куче — он трогает весь массив несколько раз и копирует его, — но не зависит от k. На собеседовании его достаточно описать словами и назвать сложность; код просят реже.

## Top K частых элементов

Частая вариация: вернуть k самых часто встречающихся значений. Сначала частоты словарём (шаблон «подсчёт частот» из `Dictionary vs HashSet на практике`), потом та же куча — только приоритетом служит частота:

```csharp
static int[] TopKFrequent(int[] nums, int k)
{
    var freq = new Dictionary<int, int>();
    foreach (int x in nums)
        freq[x] = freq.GetValueOrDefault(x) + 1;

    var heap = new PriorityQueue<int, int>(k + 1);
    foreach (var (value, count) in freq)
    {
        heap.Enqueue(value, count);
        if (heap.Count > k) heap.Dequeue();
    }
    var result = new int[heap.Count];
    for (int i = result.Length - 1; i >= 0; i--)
        result[i] = heap.Dequeue();
    return result;
}
```

O(n + u log k), где u — число уникальных значений. Для `[1, 1, 1, 2, 2, 3]` и k = 2 ответ `[1, 2]`.

Есть и линейный вариант — **bucket sort по частоте**: частота не превышает n, поэтому заводим массив из n + 1 корзин, кладём каждое значение в корзину своей частоты и идём от старших корзин к младшим, пока не наберём k. O(n) времени и O(n) памяти.

## Крайние случаи и тесты

- `k = 0` → пустой массив; отрицательное k → `ArgumentOutOfRangeException`.
- `k > n` → все элементы по убыванию: `TopK([3, 1], 5)` даёт `[3, 1]`.
- Пустой вход → пустой результат.
- Дубликаты: `[5, 5, 5, 1]`, k = 2 → `[5, 5]`. Если нужны k **различных** значений, сначала `Distinct` или `HashSet`.
- Равные частоты в top K частых: какой из элементов попадёт в ответ, не определено. Если нужен детерминизм, приоритетом делают кортеж `(count, value)` с явным правилом сравнения.

Все реализации из статьи — куча для наибольших и наименьших, quickselect, обе версии top K частых — сверены с сортировкой на трёх тысячах случайных массивов с дубликатами и случайным k, включая k = 0 и k > n.

## Вариации, которые спрашивают следом

**K-й наибольший элемент** — та же куча размера k, ответ — её вершина; или quickselect.

**K ближайших точек к началу координат** — куча с приоритетом «квадрат расстояния», без извлечения корня.

**Медиана потока** — две кучи: max-куча для нижней половины и min-куча для верхней, размеры отличаются не больше чем на единицу.

**Данные не помещаются на одну машину.** Каждый узел считает локальный top K, потом результаты сливаются ещё одной кучей. Для top K **частых** так нельзя: значение может быть десятым на каждом узле и первым в сумме. Нужно либо шардировать по ключу, чтобы все вхождения значения попадали на один узел, либо пользоваться приближёнными структурами вроде Count-Min Sketch или Space-Saving.

## Что стоит ответить на собеседовании

Уточнить соотношение k и n, нужен ли порядок, помещаются ли данные в память. Назвать сортировку за O(n log n) как базу, затем предложить min-кучу размера k: вершина — худший из кандидатов, новый элемент вытесняет его, только если больше. Итог — O(n log k) времени и O(k) памяти, и решение работает на потоке. В .NET это `PriorityQueue<TElement, TPriority>`, и это min-куча; для k наименьших нужен обратный компаратор.

Сильный ответ знает альтернативы: quickselect за O(n) в среднем, если порядок не нужен и массив можно менять, и bucket sort для top K частых. И оговаривает границы применимости: при k, близком к n, куча теряет преимущество перед сортировкой, а в распределённом варианте локальные top K частых нельзя просто слить без шардирования по ключу.
