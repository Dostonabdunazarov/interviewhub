Классов сложности, которые встречаются на собеседовании, немного: константа, логарифм, линия, n log n и квадрат, изредка экспонента. Определения выучить легко, а вот почувствовать, насколько они различаются на практике, проще всего на замерах. Все числа ниже получены на .NET 10.0.10, Windows 11, x64, Release-сборка, медиана из нескольких прогонов после прогрева.

## Сводная таблица

| Класс | Название | Шагов при n = 10⁶ | Типичный пример |
| --- | --- | --- | --- |
| O(1) | константа | 1 | `array[i]`, поиск в хеш-таблице |
| O(log n) | логарифм | ~20 | бинарный поиск, операция с кучей |
| O(n) | линейная | 10⁶ | один проход, поиск максимума |
| O(n log n) | n log n | ~2·10⁷ | сортировка |
| O(n²) | квадратичная | 10¹² | все пары элементов |
| O(2ⁿ) | экспонента | — | перебор подмножеств |

## O(1): не зависит от n

Число шагов одно и то же для массива из десяти элементов и из миллиарда:

```csharp
static int Middle(int[] items) => items[items.Length / 2];
```

Адрес элемента вычисляется арифметикой — начало массива плюс индекс, умноженный на размер элемента, — поэтому доступ по индексу не зависит от длины. Замер подтверждает: тысяча обращений по случайным индексам к массиву из миллиона элементов заняла 0,007 мс, к массиву из десяти миллионов — 0,013 мс. Разница не в десять раз, а в пределах эффектов кэша.

O(1) не значит «бесплатно». Хеш длинной строки считается по всем её символам: это O(1) относительно числа элементов в словаре, но O(длины ключа) по-честному.

## O(log n): задача делится на каждом шаге

Если каждая итерация отбрасывает постоянную долю данных, итераций будет логарифм. Канонический пример — бинарный поиск по отсортированному массиву:

```csharp
static int IndexOf(int[] sorted, int target)
{
    int lo = 0, hi = sorted.Length - 1;
    while (lo <= hi)
    {
        int mid = lo + (hi - lo) / 2;
        if (sorted[mid] == target) return mid;
        if (sorted[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

Сколько итераций делает этот цикл, если искомое меньше всех элементов массива:

```
n = 1 000              9 шагов
n = 1 000 000         19 шагов
n = 1 000 000 000     29 шагов
```

Тысячекратный рост данных добавляет десять шагов. Это свойство и делает логарифм таким ценным: удвоение входа стоит одной лишней итерации. Тонкости бинарного поиска — границы, переполнение `(lo + hi) / 2`, поиск первого вхождения — разбирает отдельная статья раздела «Приёмы».

## O(n): каждый элемент константное число раз

```csharp
static int Max(int[] items)
{
    int max = items[0];
    foreach (var x in items)
        if (x > max) max = x;
    return max;
}
```

Линейное время — нижняя граница для любой задачи, где нужно посмотреть все данные: максимум, сумма, проверка «все ли элементы положительны». Быстрее не бывает, потому что непросмотренный элемент мог изменить ответ.

Замер суммы массива: 0,59 мс на миллионе элементов и 3,73 мс на десяти миллионах. Рост примерно в шесть раз вместо десяти — на маленьком массиве сильнее сказываются накладные расходы и прогрев кэша, но порядок роста виден.

Два последовательных прохода — по-прежнему O(n): 2n отличается от n константой.

## O(n log n): сортировка и «разделяй и властвуй»

Это цена сортировки сравнениями и большинства алгоритмов, которые делят задачу пополам и делают линейную работу на каждом из log n уровней.

```
Array.Sort, 1 000 000 случайных int     69 мс
Array.Sort, 10 000 000 случайных int   813 мс
```

Рост в 11,7 раза при десятикратном увеличении входа — ровно лишний множитель log n сверх линии.

На собеседовании O(n log n) важен как промежуточная ступень: если очевидное решение квадратичное, часто помогает **сначала отсортировать**, а потом пройти один раз — соседние элементы, два указателя, бинарный поиск.

## O(n²): все пары

Вложенный цикл по одним и тем же данным:

```csharp
static bool HasDuplicatesNested(int[] items)
{
    for (int i = 0; i < items.Length; i++)
        for (int j = i + 1; j < items.Length; j++)
            if (items[i] == items[j]) return true;
    return false;
}
```

Это n(n−1)/2 сравнений. Та же задача решается сортировкой за O(n log n) и множеством за O(n):

```csharp
static bool HasDuplicatesSorted(int[] items)
{
    var copy = (int[])items.Clone();
    Array.Sort(copy);
    for (int i = 1; i < copy.Length; i++)
        if (copy[i] == copy[i - 1]) return true;
    return false;
}

static bool HasDuplicatesSet(int[] items)
{
    var seen = new HashSet<int>(items.Length);
    foreach (var x in items)
        if (!seen.Add(x)) return true;
    return false;
}
```

Замер на худшем входе — дубликатов нет, поэтому каждый вариант проходит до конца:

| n | Вложенные циклы | Сортировка | HashSet |
| --- | --- | --- | --- |
| 1 000 | 0,33 мс | 0,024 мс | 0,018 мс |
| 10 000 | 31 мс | 0,59 мс | 0,11 мс |
| 100 000 | 4 243 мс | 6,8 мс | 1,07 мс |

Квадратичный вариант растёт примерно в сто раз на каждый десятикратный рост входа, и на ста тысячах элементов он в четыре тысячи раз медленнее множества. На тысяче элементов разницы никто не заметит — поэтому O(n²) так часто доживает до продакшена и падает на первом большом клиенте.

Квадрат прячется и без явных вложенных циклов. Тот же замер для двух типичных ловушек:

| n | `list.Insert(0, x)` | `list.Add(x)` | `s += 'a'` | `StringBuilder` |
| --- | --- | --- | --- | --- |
| 1 000 | 0,06 мс | 0,009 мс | 0,14 мс | 0,012 мс |
| 10 000 | 4,0 мс | 0,064 мс | 6,4 мс | 0,037 мс |
| 100 000 | 517 мс | 0,49 мс | 3 119 мс | 0,27 мс |

Каждая вставка в начало сдвигает весь список, каждая конкатенация копирует всю строку — n раз по O(n). Почему строки так себя ведут, разобрано в статье `Строки и StringBuilder`.

## Экспонента и факториал

**O(2ⁿ)** — перебор всех подмножеств: каждый элемент либо входит, либо нет. При n = 30 это уже миллиард вариантов. **O(n!)** — перебор перестановок: 10! = 3,6 миллиона, 15! — больше триллиона.

Такие решения уместны только при очень маленьких `n` или как отправная точка, которую дальше улучшают мемоизацией и динамическим программированием (раздел «Приёмы»).

Встречаются и промежуточные классы: O(√n) у проверки числа на простоту, O(V + E) у обхода графа, O(n·k) у задач с окном размера `k`.

## Как прочитать ограничения задачи

На алгоритмической секции и в задачах с онлайн-проверкой ограничение на `n` подсказывает ожидаемую сложность. Ориентир: простой цикл на C# делает порядка 10⁸–10⁹ элементарных операций в секунду — в замере выше 5·10⁹ сравнений вложенного цикла заняли около четырёх секунд.

| Ограничение | Ожидаемая сложность |
| --- | --- |
| n ≤ 20 | O(2ⁿ), перебор |
| n ≤ 500 | O(n³) |
| n ≤ 10⁴ | O(n²) |
| n ≤ 10⁶ | O(n log n) или O(n) |
| n ≤ 10⁹ | O(log n) или O(1), формула |

На живом собеседовании ограничений часто не дают — стоит спросить самому: «сколько элементов ожидаем?» Сам вопрос показывает, что вы думаете о масштабе.

## Что стоит ответить на собеседовании

O(1) — время не зависит от размера входа (доступ по индексу, поиск в хеш-таблице в среднем); O(log n) — задача сокращается в константу раз на каждом шаге, как в бинарном поиске, где миллиард элементов требует около 30 сравнений; O(n) — один проход; O(n log n) — сортировка и «разделяй и властвуй»; O(n²) — перебор всех пар.

Сильный ответ покажет разницу числами и предложит путь улучшения: поиск дубликатов вложенными циклами на 100 000 элементах занимает больше четырёх секунд, сортировка с проходом по соседям — 7 мс, `HashSet` — около миллисекунды. Общий приём — увидев O(n²), спросить себя, нельзя ли отсортировать за O(n log n) или завести хеш-таблицу за O(n) ценой дополнительной памяти. И напомнит, что квадрат прячется в `Insert(0, …)` и конкатенации строк в цикле, а не только во вложенных `for`.
