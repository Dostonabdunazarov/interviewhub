`HashSet<T>` — это `Dictionary` без значений: те же корзины, тот же хеш, только хранятся одни ключи. Нужен он для двух вещей — быстро проверять вхождение и хранить элементы без дубликатов.

## Зачем он, если есть List

Разница — в цене проверки вхождения. `List.Contains` перебирает элементы подряд, `HashSet.Contains` считает хеш и смотрит одну корзину.

Замер на .NET 10, коллекция из 1000 элементов, 100 000 проверок:

```
List.Contains   9,95 мс
Dictionary/HashSet по ключу   1,29 мс
```

В восемь раз, и разрыв растёт с размером коллекции: у списка время линейно, у множества — почти постоянно. На десяти элементах список даже выиграет (нет вычисления хеша), на десяти тысячах проиграет на порядки.

Типичный случай, где это решает: проверка «уже обработали?» внутри цикла.

```csharp
// O(n²): для каждого элемента перебор всего списка
var processed = new List<int>();
foreach (var item in items)
{
    if (processed.Contains(item.Id)) continue;
    processed.Add(item.Id);
}

// O(n): проверка за константу
var processed = new HashSet<int>();
foreach (var item in items)
{
    if (!processed.Add(item.Id)) continue;   // Add сам вернёт false для дубликата
}
```

## Add возвращает bool

Деталь, которая позволяет не делать двойную работу. Проверено:

```
первый Add:    True
повторный Add: False
```

То есть `Add` одновременно проверяет и добавляет — отдельный `Contains` перед ним не нужен:

```csharp
// Лишний поиск
if (!set.Contains(x)) set.Add(x);

// Один поиск
set.Add(x);
```

Добавление дубликата ничего не аллоцирует — замер показал ноль байт.

## Операции над множествами

То, ради чего стоит знать `HashSet` отдельно от словаря:

```csharp
var a = new HashSet<int>(Enumerable.Range(0, 1000));
var b = new HashSet<int>(Enumerable.Range(500, 1000));

a.UnionWith(b);          // объединение: всё из обоих
a.IntersectWith(b);      // пересечение: только общие
a.ExceptWith(b);         // разность: убрать всё, что есть в b
a.SymmetricExceptWith(b);// только уникальные для каждого
```

Замер: пересечение двух множеств по 1000 элементов — **0,875 мс**, и результат 500 элементов. Через `List` это была бы вложенная пара циклов.

Есть и проверки отношений, все без изменения содержимого:

```csharp
a.IsSubsetOf(b);
a.IsSupersetOf(b);
a.Overlaps(b);           // есть ли хоть один общий
a.SetEquals(b);          // одинаковый состав, порядок не важен
```

Важно: **все эти методы меняют исходное множество** (кроме проверок). Если оригинал нужен, копируйте:

```csharp
var intersection = new HashSet<int>(a);
intersection.IntersectWith(b);
```

## HashSet против Distinct

Оба убирают дубликаты, и по скорости они сопоставимы — замер на .NET 10:

```
LINQ Distinct().ToList()   190,13 мс
new HashSet<int>(arr)      192,98 мс
```

Практически одинаково, потому что `Distinct` внутри и использует множество. Выбор — по смыслу:

```csharp
// Нужна последовательность без дубликатов, порядок сохранён
var unique = items.Distinct().ToList();

// Нужна структура для последующих проверок вхождения
var lookup = new HashSet<int>(ids);
```

`Distinct` **сохраняет порядок** первого появления, `HashSet` порядок не гарантирует вовсе — как и словарь (см. `Как устроен Dictionary`).

Для группировки по ключу с сохранением всех элементов есть `ILookup`:

```csharp
ILookup<string, Order> byCustomer = orders.ToLookup(o => o.CustomerId);
```

## Требования к элементу

Те же, что к ключу словаря, и по той же причине:

- корректные `Equals` и `GetHashCode`, согласованные между собой;
- неизменяемость полей, участвующих в хеше.

Проверено на .NET 10 — мутация после вставки теряет элемент:

```csharp
var key = new MutableKey { Value = 1 };
var set = new HashSet<MutableKey> { key };
key.Value = 2;
set.Contains(key);   // false, хотя это тот самый объект
```

Для своих типов-значений это сильный довод за `record` (см. `class, struct и record`): равенство и хеш генерируются корректно и по всем полям.

Компаратор задаётся так же, как у словаря:

```csharp
var set = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
set.Add("Admin");
set.Contains("ADMIN");   // true
```

## Когда HashSet не нужен

**Элементов мало.** На десятке значений линейный поиск по массиву быстрее: нет вычисления хеша, и данные лежат подряд в кэше. Граница примерно в районе нескольких десятков элементов, и точное значение зависит от типа.

**Нужен порядок.** `HashSet` его не хранит. Если нужен отсортированный набор — `SortedSet<T>`: он на дереве, даёт O(log n) вместо O(1), зато перечисляется по возрастанию и умеет диапазонные запросы:

```csharp
var sorted = new SortedSet<int>(numbers);
var range = sorted.GetViewBetween(10, 20);
```

**Нужны дубликаты или счётчик** — тогда `Dictionary<T, int>` со счётчиком вхождений.

**Нужен доступ по индексу** — множество его не предоставляет.

**Многопоточный доступ.** `HashSet` не потокобезопасен; готового `ConcurrentHashSet` в платформе нет, поэтому используют `ConcurrentDictionary<T, byte>` и игнорируют значение.

## Память

`HashSet` устроен как словарь без поля значения, поэтому на элемент тратит меньше, чем `Dictionary`, но заметно больше, чем список: те же записи с хешом и ссылкой на следующую плюс массив корзин и запас ёмкости. Для миллионов элементов это стоит закладывать в расчёты — ориентир по порядку величины даёт замер словаря: 23,3 байта на элемент против 3,9 у `List<int>`.

Как и везде, `capacity` стоит задавать заранее, если размер известен:

```csharp
var set = new HashSet<int>(capacity: expectedCount);
```

## Что стоит ответить на собеседовании

`HashSet<T>` — хеш-таблица без значений: хранит уникальные элементы и проверяет вхождение за константу вместо линейного перебора. На коллекции из 1000 элементов это 1,29 мс против 9,95 мс у `List.Contains` (замер на .NET 10), и разрыв растёт с размером, поэтому проверка «видели ли мы это» внутри цикла по списку — классическая O(n²), которая лечится заменой на множество.

Сильный ответ добавит, что `Add` возвращает `bool` и совмещает проверку с добавлением, что операции над множествами (`UnionWith`, `IntersectWith`, `ExceptWith`) изменяют исходную коллекцию и требуют копии, если оригинал нужен, и что требования к элементу те же, что к ключу словаря: согласованные `Equals`/`GetHashCode` и неизменяемость хеш-полей — иначе элемент теряется в наборе после мутации.
