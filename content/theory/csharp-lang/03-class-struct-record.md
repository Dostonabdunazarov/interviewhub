В C# четыре способа объявить тип с данными: `class`, `struct`, `record` и `record struct`. Различаются они по двум независимым осям — как тип передаётся и как он сравнивается, — и путаница обычно возникает из-за того, что эти оси считают одной.

## Две оси вместо одной

**Первая ось — семантика передачи.** Ссылочная или значимая. Про неё была отдельная статья: `class` и `record` передаются по ссылке, `struct` и `record struct` копируются.

**Вторая ось — семантика равенства.** По ссылке или по значению. `class` и `struct` ведут себя по-разному, а `record` меняет поведение обоих.

Отсюда таблица:

| | Равенство по ссылке | Равенство по значению |
|---|---|---|
| **Ссылочный тип** | `class` | `record` |
| **Значимый тип** | — | `struct`, `record struct` |

`record` — это класс, которому компилятор дописал сравнение по содержимому. `record struct` — структура, которой компилятор дописал то же самое эффективнее, чем базовая реализация.

Пустой клетки в таблице нет: структура всегда сравнивается по значению, просто у обычной `struct` это делается медленной реализацией по умолчанию.

## Что генерирует record

`record` — не новый вид типа, а `class` с набором автоматически сгенерированных членов. Объявление в одну строку:

```csharp
public record Person(string FirstName, string LastName);
```

разворачивается компилятором примерно в такой класс:

- **конструктор** с параметрами `FirstName` и `LastName`;
- **свойства только для чтения** с `init`-сеттерами;
- **`Equals` и `GetHashCode`** по всем полям;
- **операторы `==` и `!=`**, которые вызывают `Equals` — в отличие от обычного класса;
- **метод `<Clone>$`** и поддержка выражения `with`;
- **`ToString`**, печатающий `Person { FirstName = Иван, LastName = Петров }`;
- **`Deconstruct`** для разложения на переменные.

Проверить это можно в SharpLab — он показывает сгенерированный код целиком.

```csharp
var p1 = new Person("Иван", "Петров");
var p2 = new Person("Иван", "Петров");

p1 == p2;           // true — у record операторы сравнивают содержимое
ReferenceEquals(p1, p2);  // false — объекты разные

var p3 = p1 with { LastName = "Сидоров" };  // копия с изменённым полем
p1.ToString();      // Person { FirstName = Иван, LastName = Петров }
```

Позиционный синтаксис — не обязателен. Тело у записи такое же, как у класса:

```csharp
public record Person
{
    public required string FirstName { get; init; }
    public string? MiddleName { get; init; }

    public string FullName => $"{FirstName} {MiddleName}".Trim();
}
```

## Где record ведёт себя не так, как ожидают

### Равенство по значению не рекурсивное для коллекций

Сгенерированный `Equals` сравнивает поля через `EqualityComparer<T>.Default`. Для строк и чисел это сравнение по содержимому, а для массива или `List<T>` — по ссылке, потому что у коллекций нет структурного равенства.

```csharp
public record Basket(string Owner, List<string> Items);

var a = new Basket("Иван", ["хлеб"]);
var b = new Basket("Иван", ["хлеб"]);

a == b;   // false — списки разные объекты
```

Это регулярно удивляет. Если запись содержит коллекцию и равенство должно быть по содержимому, `Equals` придётся писать руками или использовать неизменяемую коллекцию со структурным сравнением.

### `with` делает поверхностную копию

Выражение `with` копирует поля как есть. Ссылочное поле останется общим для оригинала и копии:

```csharp
var original = new Basket("Иван", ["хлеб"]);
var copy = original with { Owner = "Пётр" };

copy.Items.Add("молоко");
// original.Items тоже содержит "молоко" — список один
```

Ровно та же логика, что у присваивания ссылочных типов из первой статьи. `with` не делает глубокого клонирования и не пытается.

### Наследование влияет на равенство

Две записи разных типов не равны, даже если все поля совпадают. Компилятор генерирует защищённое свойство `EqualityContract`, и `Equals` сравнивает в том числе его.

```csharp
public record Person(string Name);
public record Employee(string Name) : Person(Name);

Person a = new Person("Иван");
Person b = new Employee("Иван");
a == b;   // false — разные EqualityContract
```

Это правильное поведение: сотрудник — не то же самое, что человек с тем же именем. Но оно отличается от наивного «сравнить все поля», и его стоит знать.

### record не делает тип неизменяемым автоматически

Позиционный синтаксис даёт `init`-свойства, и такая запись действительно неизменяема. Но запись с обычным телом может содержать что угодно:

```csharp
public record Mutable
{
    public string Name { get; set; }   // обычный сеттер — запись изменяема
}
```

`record` — про равенство по значению, а не про неизменяемость. Они часто идут вместе, но это разные вещи.

## record struct

`record struct` появился в C# 10 и делает для структуры то же, что `record` для класса, — но выигрыш здесь другой.

Обычная структура **уже** сравнивается по значению: базовая реализация `ValueType.Equals` перебирает поля. Проблема в том, что делает она это через рефлексию, если структура содержит хотя бы одно поле ссылочного типа. Это на порядки медленнее, и попутно упаковывает аргумент.

`record struct` генерирует `Equals(T)` строго типизированным кодом, реализует `IEquatable<T>` и избавляет от упаковки:

```csharp
public readonly record struct Money(decimal Amount, string Currency);
```

Одна строка даёт неизменяемую структуру с быстрым сравнением, корректным `GetHashCode`, `ToString` и `with`. Для маленького значимого типа это сегодня лучший способ объявления.

Важное отличие от `record`: по умолчанию `record struct` **изменяемый** — его свойства получают обычные сеттеры. `readonly` нужно писать явно, и для структуры это почти всегда правильно.

## Как выбирать

Практический порядок решений.

**Нужна идентичность — берите `class`.** Сущность, у которой есть свой жизненный цикл и которая остаётся собой при изменении полей: заказ, пользователь, соединение с базой. Два заказа с одинаковыми полями — это два разных заказа.

**Нужно значение с равенством по содержимому — берите `record`.** DTO, событие, ответ API, ключ кэша, параметры запроса. Здесь два объекта с одинаковыми полями логически одно и то же, а `with`, `ToString` и `Deconstruct` идут бесплатно.

**Нужно маленькое неизменяемое значение в горячем коде — берите `readonly record struct`.** Деньги, координата, идентификатор, диапазон. Критерии те же, что для структуры вообще: около 16 байт, неизменяемость, короткое время жизни.

**Обычный `struct` без `record`** остаётся для случаев, когда нужен точный контроль над разметкой памяти или совместимость с нативным кодом — то есть редко.

Ещё один практический довод в пользу `record` для DTO: сгенерированный `ToString` печатает содержимое, а не имя типа. В логах и при отладке это экономит заметно больше времени, чем кажется.

## Что стоит ответить на собеседовании

`class` — ссылочный тип с равенством по ссылке. `struct` — значимый тип с равенством по значению. `record` — это класс, которому компилятор сгенерировал равенство по содержимому, `with`, `ToString` и `Deconstruct`. `record struct` — то же для структуры, но там выигрыш не в самом равенстве по значению, которое у структуры уже есть, а в скорости: генерируется типизированный `Equals` вместо медленной реализации через рефлексию.

Сильный ответ добавит, что `record` — про равенство, а не про неизменяемость, что `with` делает поверхностную копию и что запись с коллекцией внутри сравнивается по ссылке на эту коллекцию.
