Разделение на значимые и ссылочные типы — первое, что нужно понять про C#, потому что из него следует почти всё остальное: почему структуру копируют, почему `null` бывает только у классов, откуда берётся упаковка и почему два одинаковых объекта не равны друг другу.

## Два вопроса вместо одного

Когда спрашивают «в чём разница между value type и reference type», обычно ждут ответа «одни в стеке, другие в куче». Это неточно, и дальше мы разберём почему. Разница фундаментальнее и лежит не в том, **где** хранится значение, а в том, **что именно содержит переменная**.

Переменная значимого типа содержит само значение. Переменная ссылочного типа содержит ссылку — адрес, по которому лежит объект.

```csharp
int a = 5;
int b = a;      // b — независимая копия: две пятёрки в двух местах
b = 10;
// a == 5

int[] x = [1, 2, 3];
int[] y = x;    // y — вторая ссылка на тот же массив
y[0] = 99;
// x[0] == 99
```

Во втором случае массив один, а переменных две. Это и есть вся разница, из которой растут остальные различия.

## Что к чему относится

**Значимые типы:** все числовые (`int`, `double`, `decimal`), `bool`, `char`, любые `struct`, любые `enum`, кортежи `ValueTuple`, а также `DateTime`, `Guid`, `TimeSpan` — это структуры, хотя по виду не отличаются от классов.

**Ссылочные типы:** `class`, `interface`, `delegate`, массивы, `string` и `object`.

`string` в этом списке выглядит странно: он ведёт себя как значимый тип — сравнивается по содержимому, не меняется после создания. Но это ссылочный тип с особым поведением, и разбирается он отдельно, в статье про строки.

## Присваивание копирует

Из «переменная содержит само значение» следует, что присваивание значимого типа копирует все его поля.

```csharp
struct Point
{
    public int X;
    public int Y;
}

var p1 = new Point { X = 1, Y = 2 };
var p2 = p1;     // копия: скопированы оба поля
p2.X = 100;
// p1.X по-прежнему 1
```

С классом то же присваивание копирует только ссылку — объект остаётся один:

```csharp
class Box { public int Value; }

var b1 = new Box { Value = 1 };
var b2 = b1;     // копия ссылки, не объекта
b2.Value = 100;
// b1.Value == 100 — это тот же объект
```

Копирование при передаче в метод работает так же: значимый тип уходит копией, ссылочный — копией ссылки. Поэтому метод может изменить поля переданного объекта, но не может заменить сам объект — если только параметр не помечен `ref`.

## Где это действительно хранится

Теперь к «стеку и куче». Фраза «значимые типы живут в стеке» — распространённое упрощение, и на собеседовании его стоит уточнить.

Правильнее так: **значение хранится там, где объявлена переменная**.

- Локальная переменная типа `int` — в стеке текущего вызова.
- Поле `int` внутри класса — в куче, вместе с объектом, которому оно принадлежит.
- Элемент `int[]` — в куче, внутри массива.
- Захваченная лямбдой локальная переменная — в куче, потому что компилятор переносит её в сгенерированный класс замыкания.

```csharp
class Order
{
    public int Id;          // в куче: часть объекта Order
    public DateTime Date;   // тоже в куче, хотя DateTime — структура
}

void Process()
{
    int local = 5;          // в стеке
    var order = new Order();// ссылка в стеке, объект в куче
}
```

Структура в поле класса не «переезжает в стек» — она лежит внутри объекта в куче. Обратное тоже верно: у структуры нет отдельного заголовка объекта, она занимает ровно столько, сколько её поля.

Есть и третье место: статические поля живут в специальной области, привязанной к типу, а не к экземпляру, и живут до конца работы приложения.

Разница между стеком и кучей важна не сама по себе, а по последствиям: стек освобождается автоматически при выходе из метода, куча — работой сборщика мусора. Поэтому аллокации в куче стоят дороже, и снижение их числа — отдельная тема, которая разбирается в разделе про CLR и память.

## Значения по умолчанию и null

У ссылочного типа есть значение «ссылки нет» — `null`. У значимого типа его нет: структура всегда существует, её поля просто заполнены нулями.

```csharp
Box? box = null;    // нормально
int number = null;  // не компилируется

int number2 = default;        // 0
Point point = default;        // X = 0, Y = 0
int? nullable = null;         // это Nullable<int> — структура с флагом HasValue
```

`int?` — не исключение из правила, а синтаксис для `Nullable<int>`: структура, которая хранит значение и признак его наличия. Сама она значимый тип и `null` в смысле «отсутствующая ссылка» не содержит.

Из отсутствия `null` следует практическое удобство: структуру не нужно проверять перед обращением, `NullReferenceException` на ней не случится. Но следует и ограничение: «значение не задано» приходится выражать отдельно — через `Nullable<T>` или через специальное значение вроде `DateTime.MinValue`, что обычно хуже.

## Равенство по умолчанию разное

Два значимых типа равны, если равны их поля. Два ссылочных — если это один и тот же объект.

```csharp
var p1 = new Point { X = 1, Y = 2 };
var p2 = new Point { X = 1, Y = 2 };
// p1.Equals(p2) — true: поля совпадают

var b1 = new Box { Value = 1 };
var b2 = new Box { Value = 1 };
// b1.Equals(b2) — false: это разные объекты
```

Здесь прячется тонкость, из-за которой структуры бывают неожиданно медленными. Базовая реализация `ValueType.Equals` сравнивает поля через рефлексию, если структура содержит хотя бы одно поле ссылочного типа или поля не упакованы плотно. Для структуры, которую кладут в `Dictionary` или часто сравнивают, это заметно — поэтому `Equals` и `GetHashCode` у таких структур переопределяют вручную. Подробнее — в статье про `Equals`, `GetHashCode` и `==`.

## Когда выбирать struct

Практическое правило от команды .NET: структура уместна, если выполняются все условия сразу.

- Она **маленькая** — ориентир около 16 байт, то есть три-четыре поля. Большую структуру дорого копировать, и выигрыш от отсутствия аллокации съедается копированием.
- Она **неизменяемая**. Изменяемые структуры ведут себя контринтуитивно: при чтении из коллекции или свойства вы получаете копию, и изменение уходит в никуда.
- Она **логически представляет одно значение** — точку, деньги, диапазон дат, а не сущность с идентичностью.
- У неё **короткое время жизни** или она лежит в массиве, где отсутствие лишних аллокаций действительно экономит.

Во всех остальных случаях класс — правильный выбор по умолчанию. Соблазн «сделаю структуру, будет быстрее» чаще приводит к обратному: лишним копиям и незаметной упаковке.

Изменяемость стоит подчеркнуть отдельно, потому что на ней ошибаются чаще всего:

```csharp
// Так делать не надо: изменяемая структура
struct MutablePoint { public int X; }

var list = new List<MutablePoint> { new() { X = 1 } };
// list[0].X = 100;  — не скомпилируется: list[0] возвращает копию

var array = new MutablePoint[] { new() { X = 1 } };
array[0].X = 100;   // а так скомпилируется и сработает
```

Массив здесь ведёт себя иначе, чем список, потому что индексатор массива даёт прямой доступ к элементу, а индексатор `List<T>` — это метод, возвращающий копию. Разное поведение у двух похожих коллекций — ровно тот сорт сюрприза, ради избежания которого структуры делают неизменяемыми.

Современный способ объявить неизменяемую структуру короткий:

```csharp
public readonly struct Money
{
    public decimal Amount { get; init; }
    public string Currency { get; init; }
}
```

`readonly` на уровне типа запрещает изменение полей и позволяет компилятору не делать защитных копий при вызове методов — это ещё и небольшая оптимизация.

## Что стоит ответить на собеседовании

Коротко: переменная значимого типа хранит значение, ссылочного — ссылку на объект. Отсюда копирование при присваивании, отсутствие `null` у структур и равенство по полям вместо равенства по ссылке.

На уточняющий вопрос про стек и кучу стоит сказать, что значение хранится там, где живёт переменная: локальная переменная — в стеке, поле класса — в куче вместе с объектом, элемент массива — в куче. Формулировка «значимые всегда в стеке» неверна, и её проверяют именно на этом.
