# Факты: C#

## string.GetHashCode() меняется при каждом запуске

```yaml
slug: string-gethashcode-randomizirovan
category: csharp
```

В .NET Core и новее хеш строки рандомизирован: у каждого процесса свой seed, поэтому `"hello".GetHashCode()` в двух запусках подряд даёт разные числа. Так сделано для защиты от hash flooding — атаки, когда злоумышленник подбирает ключи с одинаковым хешем и превращает `Dictionary` в связный список.

Отсюда правило: `GetHashCode` нельзя сохранять в БД, кэш или файл и нельзя использовать для шардирования между машинами. Нужен стабильный хеш — берите `XxHash64`, `SHA256` или свою детерминированную функцию.

## List<T> растёт удвоением, и это видно в профайлере

```yaml
slug: list-capacity-udvaivaetsya
category: csharp
```

Пустой `new List<T>()` не выделяет массив вовсе. Первый `Add` создаёт массив на 4 элемента, дальше при переполнении ёмкость удваивается: 4 → 8 → 16 → 32… Каждый рост — новый массив и копирование всех элементов, а старый массив уходит в мусор.

Для списка на миллион элементов это два десятка переаллокаций, а последние массивы ещё и попадают в LOH. Если размер известен заранее, передайте его в конструктор: `new List<T>(count)`. То же касается `Dictionary`, `HashSet` и `StringBuilder`.

## foreach по List<T> не аллоцирует, а по IEnumerable<T> — да

```yaml
slug: foreach-struct-enumerator
category: csharp
```

`foreach` не требует интерфейса: компилятор ищет метод `GetEnumerator()` по шаблону. У `List<T>` он возвращает `List<T>.Enumerator` — структуру, которая живёт на стеке. Но стоит привести список к `IEnumerable<T>`, и вызывается интерфейсный метод: структура упаковывается в кучу.

```csharp
foreach (var x in list) { }
IEnumerable<int> e = list;
foreach (var x in e) { }
```

Первый цикл — 0 байт, второй — 40 байт на каждый проход. В горячем коде принимайте конкретный тип или `ReadOnlySpan<T>`, а не `IEnumerable<T>`.

## Лямбда в цикле for видит последнее значение счётчика

```yaml
slug: zamykanie-v-cikle-for
category: csharp
```

С C# 5 переменная `foreach` создаётся заново на каждой итерации, и замыкания захватывают «свою» копию. А вот у `for` переменная одна на весь цикл, и все лямбды смотрят на неё.

```csharp
for (int i = 0; i < 3; i++) actions.Add(() => Console.Write(i));
```

Вызов всех действий напечатает `333`, а не `012`: к моменту вызова цикл закончился и `i == 3`. Лечится локальной копией внутри тела: `var copy = i;`.

## (object)1 == (object)1 — это false

```yaml
slug: boxing-sravnenie-ssylok
category: csharp
```

Оператор `==` для `object` сравнивает ссылки. Каждая упаковка `int` создаёт новый объект в куче, поэтому две упакованные единицы — разные объекты, и результат `false`. При этом `Equals` сравнивает значения и вернёт `true`.

Ловушка всплывает в обобщённом коде без ограничений, при работе с `object`-полями и в словарях `Dictionary<string, object>`. Для сравнения значений используйте `Equals` или `EqualityComparer<T>.Default.Equals(a, b)`.
