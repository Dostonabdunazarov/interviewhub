# Вопросы для импорта

Файл читает `tools/import-questions.mjs` и заливает содержимое через админ-API.
Формат намеренно простой: заголовок `##` — это вопрос, YAML-блок под ним —
метаданные, дальше свободный Markdown до следующего `##` — ответ.

Ответ попадает в БД как есть, поэтому в нём можно использовать всё, что умеет
рендерер на фронте: списки, таблицы, `**жирный**`, блоки кода с подсветкой.

## Справочники

| Поле | Допустимые значения |
| --- | --- |
| `category` | slug категории: `react`, `dotnet`, `postgresql`, `devops`, `algorithms`, `system-design`, `soft-skills` — либо любой новый, он создастся |
| `level` | `intern`, `junior`, `middle`, `senior`, `lead` |
| `difficulty` | 1–5 |
| `status` | `draft`, `published`, `archived` (по умолчанию `published`) |
| `featured` | `true` / `false` — вывод на главной |
| `tags` | список через запятую, отсутствующие создаются |
| `companies` | `slug:год:этап`, этап — `screening`, `technical`, `system-design`, `final` |

Обязательны только `category` и `level`. Остальное имеет значения по умолчанию.

## Что такое замыкание (closure) в JavaScript?

```yaml
category: javascript
level: junior
difficulty: 2
featured: true
tags: closures, scope, functions
companies: yandex:2024:technical, ozon:2023:screening
```

Замыкание — это функция вместе с областью видимости, в которой она была
создана. Функция «помнит» переменные внешнего скоупа даже после того, как
внешняя функция завершилась.

```js
function counter() {
  let count = 0;            // живёт в замыкании
  return () => ++count;
}

const next = counter();
next(); // 1
next(); // 2
```

**Почему `count` не исчезает.** Обычно локальные переменные умирают вместе с
вызовом функции. Но возвращённая стрелочная функция ссылается на `count`, и
сборщик мусора не может освободить эту переменную, пока жива ссылка на саму
функцию. Скоуп остаётся в памяти.

**Где это нужно на практике:**

- приватное состояние без классов — переменную снаружи не достать;
- фабрики функций (`multiplier(2)`, `multiplier(3)`);
- мемоизация и кэши — кэш хранится в замыкании, а не в глобальной области;
- обработчики, которым нужны данные с момента подписки.

**Классическая ловушка** — `var` в цикле:

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));   // 3, 3, 3
}
```

`var` имеет функциональную область видимости, поэтому все три колбэка
замкнулись на одну и ту же переменную, и к моменту их выполнения она равна 3.
С `let` создаётся отдельная привязка на каждой итерации, и вывод будет `0, 1, 2`.

**Про утечки.** Замыкание держит весь свой скоуп, а не только используемые
переменные. Если в нём осталась ссылка на большой объект или DOM-узел, он не
будет собран — типичная причина утечек в долгоживущих обработчиках.

## Чем отличаются value type и reference type в C#?

```yaml
category: csharp
level: junior
difficulty: 2
tags: value-types, memory, stack, heap
companies: epam:2024:technical
```

Разница в том, что хранит переменная: сами данные или ссылку на них.

| | Value type | Reference type |
| --- | --- | --- |
| Что в переменной | значение | ссылка на объект |
| Где обычно живёт | стек или инлайн в объекте | куча |
| Присваивание | копирует значение | копирует ссылку |
| Значение по умолчанию | нули полей | `null` |
| Примеры | `int`, `bool`, `double`, `struct`, `enum`, `DateTime` | `class`, `string`, массив, делегат, `object` |

```csharp
struct PointS { public int X; }
class  PointC { public int X; }

var s1 = new PointS { X = 1 };
var s2 = s1;          // копия значения
s2.X = 99;            // s1.X == 1

var c1 = new PointC { X = 1 };
var c2 = c1;          // копия ссылки
c2.X = 99;            // c1.X == 99 — тот же объект
```

**Про «value type всегда в стеке» — это упрощение.** Поле-структура внутри
класса лежит в куче вместе с этим объектом, а захваченная замыканием или
`async`-методом переменная переезжает в сгенерированный компилятором класс.
Правильнее говорить: value type хранится там, где объявлен, без отдельного
объекта в куче.

**Практические следствия:**

- **Мутация копии.** Метод, меняющий поле структуры, полученной по значению,
  меняет копию — исходник остаётся прежним. Отсюда правило делать структуры
  неизменяемыми (`readonly struct`).
- **Боксинг.** Приведение value type к `object` или интерфейсу упаковывает
  его в куче. В горячем цикле это заметная нагрузка на GC.
- **Сравнение.** У структур `==` по умолчанию не определён, `Equals`
  сравнивает поля. У классов сравнение по ссылке, если не переопределено.
  `record` и `record struct` генерируют сравнение по значению сами.
- **`null`.** Value type не может быть `null` без `Nullable<T>` (`int?`).

**Когда выбирать структуру:** маленький (ориентир — до ~16 байт), логически
неизменяемый набор полей с семантикой значения — координата, деньги,
идентификатор. Во всех остальных случаях класс.
